# Design Token 字段规范

> 原则：**够用即可。** token 越多，生成页面时被忽略的概率越高，风格反而越散。
> 一个真实项目通常 30–45 个变量就够；超过 80 个说明你在把一次性样式塞进 token。

## 一、命名约定

统一前缀 + 语义命名，**禁止**用视觉值命名（如 `--blue-500`），要用用途命名（如 `--color-primary`）。
理由：`--blue-500` 在换主题时会变成语义谎言。

```
--{类别}-{语义}[-{变体}]
```

| 类别前缀 | 含义 | 示例 |
|---|---|---|
| `--color-` | 功能色与语义色 | `--color-primary` `--color-danger` |
| `--gray-` | 中性色阶（按数值分级） | `--gray-50` `--gray-900` |
| `--bg-` | 背景 | `--bg-base` `--bg-subtle` |
| `--fg-` | 前景（文字） | `--fg-base` `--fg-muted` |
| `--font-` | 字体族 | `--font-sans` `--font-mono` |
| `--text-` | 字号（含行高单独一条） | `--text-md` `--leading-md` |
| `--space-` | 间距 | `--space-4` |
| `--radius-` | 圆角 | `--radius-md` |
| `--shadow-` | 阴影 | `--shadow-1` |
| `--bp-` | 断点（仅文档用，媒体查询里写实际值） | 见第五节 |

## 二、分级数量（写多写少都错）

| 类别 | 建议级数 | 少于会怎样 | 多于会怎样 |
|---|---|---|---|
| 功能色 | 4（主 / 成功 / 警告 / 错误） | 状态表达不出来 | 记不住，随手造新色 |
| 中性色阶 | 5 级（50/100/300/600/900） | 层级拉不开 | 相邻两级肉眼分不出，等于没分 |
| 字号 | 4–5 级 | 全篇一样大 | 生成时随手挑，层级乱 |
| 间距 | 4–6 级 | 元素贴一起 | 同上 |
| 圆角 | 2–3 级 | 卡片和按钮一个圆角 | 无意义 |
| 阴影 | 2 级 | 浮层没层次 | 阴影过重显脏 |

**8 项最小集合**（SKILL.md 规则 3 要求）：主色、语义三色、中性色阶≥5、背景色、前景色、字体族、字号阶梯≥4、间距节奏≥4。
圆角与阴影为建议项，可标「未提供」。

## 三、中性色阶怎么取

从参考物里找到**最深的前景**与**最浅的背景**，中间按感受均匀插值：

```
--gray-50  最浅，用于次级背景、hover 底色
--gray-100 分隔线、禁用背景
--gray-300 边框、占位符
--gray-600 辅助文字、图标
--gray-900 主文字、标题
```

判定纪律：五级里必须有一级能当边框（`--gray-300` 附近），必须有一级能当辅助文字（`--gray-600` 附近）。
取不到就按 `#1F2329 → #6B7280 → #C9CED6 → #EDEFF2 → #F7F8FA` 这套中性默认值补齐，并标 `[推断]`。

## 四、字号阶梯与行高

字号阶梯建议按 **1.25 倍**递进（模块化比例，Major Third）：

| 变量 | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px | 辅助说明、角标 |
| `--text-sm` | 14px | 次要正文、表格 |
| `--text-md` | 16px | 正文基准 |
| `--text-lg` | 20px | 小标题 |
| `--text-xl` | 28px | 区块标题 |
| `--text-2xl` | 36px | 页面主标题 |

**行高必须单独成一条变量**，不要写进 `font` 简写：
```
--leading-tight: 1.25;   /* 标题 */
--leading-md:    1.6;    /* 正文 */
```
参考物里量不出精确行高时，正文取 1.6、标题取 1.25，标 `[推断]`。

## 五、断点与栅格

断点**不写成 CSS 变量**（`var()` 不能用在媒体查询里），在 token 文件里用注释声明，生成页面时写实际值：

```css
/* 断点：sm 640px / md 768px / lg 1024px / xl 1280px */
/* 栅格：12 列，间距 --space-4，容器最大宽 1200px */
```

| 变量 | 值 | 说明 |
|---|---|---|
| `--container-max` | 1200px | 内容区最大宽度 |
| `--grid-cols` | 12 | 栅格列数 |
| `--grid-gap` | `var(--space-4)` | 栅格间距 |

## 六、字体族降级栈写法

参考物用的是商业字体时，**必须**替换并注明替代关系：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC",
             "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
```

标注方式：
```
/* 原站使用 XXX Sans（商业授权），已替换为系统字体栈，视觉接近 */
```

**禁止**引用商业字体的 CDN 链接（授权风险，见 SKILL.md 规则 6）。

## 七、暗色主题（可选，用户要时才做）

不要默认生成暗色 token。用户明确要时，用 `[data-theme="dark"]` 覆盖同名变量，**不要**另起一套变量名：

```css
[data-theme="dark"] {
  --bg-base: var(--gray-900);
  --fg-base: var(--gray-50);
}
```

这样页面代码一行都不用改。

## 八、自检清单

生成完 token 文件后逐项过一遍：

1. 8 项最小集合齐全吗？缺的标 `[推断]` 了吗？
2. 有 `--blue-500` 这类用视觉值命名的变量吗？（应改为用途命名）
3. 中性色阶里能找出「当边框的」和「当辅助文字的」两级吗？
4. 行高是独立变量吗？
5. 断点写进 `var()` 了吗？（写了会失效）
6. 商业字体 CDN 引用清掉了吗？
7. 文件头标了来源与生成日期吗？
8. 变量总数超过 80 了吗？（超了就砍掉只在单页出现的一次性样式）
