# 提取方法与脚本用法

## 一、网页参考：用脚本取候选值

```bash
python3 scripts/fetch-page-css.py <url> [--limit 25] [--timeout 20] [--css-only]
```

脚本会：抓 HTML → 收集 `<style>` 内联样式 → 抓最多 12 个外链 CSS → 统计颜色/字号/间距/圆角/阴影/字体族的出现频次。

**`--css-only`**：只输出「CSS 变量（令牌）」一段，跳过其余候选段 —— 原站已令牌化、只想要命名与值时用它。

**编码**：脚本自动按「HTTP `Content-Type` 的 charset → 页面 `<meta charset>` → CSS `@charset`」的顺序嗅探字符编码。
三种都找不到、或声明的编码解不开时，会在 **stderr 打印编码警告并说明「非 ASCII 内容可能丢失」** ——
看到该警告就说明提取到的中文值（字体名等）**可能已经不可信**，此时改用页面截图作参考物，不要照抄。


**看结果的优先级：**

1. **先看「CSS 变量」那一段。** 如果原站已经做了令牌化（`--color-primary: #xxx`），直接沿用它的命名和值，这是最省事也最准的路径。
2. 再看颜色频次榜。**频次最高 ≠ 主色**，要结合用途判断：频次最高的经常是边框色或背景灰。
   主色通常出现在：按钮背景、链接、选中态、品牌 logo 附近。
3. 字号榜里挑出现 4–6 个不同值的作为阶梯，过滤掉 10px 以下的装饰性字号。
4. 间距榜里挑能被 4 整除的值（4/8/12/16/24/32），这是主流设计系统的节奏。

**脚本说「抓不到」时：**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 抓取失败，报超时/证书错 | 站点不可达或反爬 | 请用户提供截图，或换一个可访问的页面 |
| 拿到了但样式极少（<200 字符） | 纯前端渲染（SPA），样式在 JS 里 | 改用截图；**不要**根据这点内容生成配色 |
| 外链 CSS 抓不全 | 跨域或 CDN 限制 | 已抓到的够用就继续，不够就补截图 |
| 颜色全在 JS 里（如 styled-components） | 运行时注入 | 改用截图取色 |

## 二、截图参考：怎么取色才准

截图没有 DOM，靠肉眼/工具读像素。纪律：

1. **取大面积色块，不取抗锯齿边缘。** 边缘像素是混色，取出来是脏值。
2. **同一元素取 2–3 个点比对**，一致才采信。
3. **优先取这些位置的色：** 主按钮背景、页面主背景、标题文字、分隔线、卡片背景。
4. **不要从渐变里取单一值。** 渐变要取起点和终点两个值，在 token 里写成两个变量（如 `--color-primary-from` / `--color-primary-to`）。
5. 分辨率太低导致取不准时，明确说「主色只能取到近似值 `#5B8DEF`（±2），建议确认」——**这是合格输出，不是失败**（见 SKILL.md 第六节）。

## 三、只有文字描述时（B 路径）

用户说「要一个科技感、蓝色调的后台」，没有参考物。这时：

1. 生成 token **草案**，文件头必须写：`/* 草案·未经参考物校准 */`。
2. 配色按语义生成，但**每一个值都要标 `[推断]`**。
3. 明确告诉用户：「这套配色是按描述推断的，给我一个参考链接或截图可以校准到更准。」
4. **禁止**把草案说成「根据您参考的设计提取的」——那是编造来源。

## 四、三类来源的标注方式

token 文件里每个不确定值都要能看出来源：

```css
--color-primary: #5B8DEF;   /* 提取自 .btn-primary 背景色 */
--space-5: 20px;            /* [推断] 原站未出现，按 4px 节奏补齐 */
--radius-lg: 16px;          /* 未提供，暂按 0 处理 */
```

来源三分类（与 SKILL.md 第六节一致）：
- **用户提供的** —— 用户明确给了值
- **我从参考物提取的** —— 必须写出具体位置（选择器/元素/坐标）
- **我推断的** —— 必须标 `[推断]` 或 `未提供`

## 五、常见坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 把 hover 态的深色当主色 | 整体偏暗 | 取按钮常态色，hover 另外单独一个变量 |
| 把半透明遮罩色当背景 | 叠起来发灰 | 半透明值单独命名 `--bg-overlay`，别混进 `--bg-base` |
| 从压缩过的 CSS 里取到 `!important` 覆盖链 | 取到被废弃的旧值 | 以频次 + 视觉判断为准，不一致时优先相信截图 |
| 忽略了深色模式 | 只做了浅色 | 用户没提深色就只做浅色，不要自作主张加 |
| 一次把 50 个颜色都搬进 token | 风格散 | 只保留 8 项最小集合 + 少量确实复用的 |
