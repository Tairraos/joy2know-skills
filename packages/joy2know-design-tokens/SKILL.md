# 晓得 · 设计解剖

> 把「一个设计参考」变成「一份 token 文件 + 按 token 生成的多页代码」。
> 中间那层文件是全部价值所在——没有它，风格就只存在于单次对话里。

## 一、先分清（不做这一步后面全错）

| 概念 | 判定标准 | 处理方式 |
|---|---|---|
| **Token（令牌）** | 一个可被代码引用的命名值，如 `--color-primary: #5B8DEF` | 必须落进 token 文件，页面只引用不内联 |
| **一次性样式** | 只在某一页出现、换页就失效的具体数值 | 允许写在该页，但**不得**是主色/主字体/基础间距 |
| **风格** | 配色 + 字号阶梯 + 间距节奏 + 圆角 + 阴影的组合 | 全部进 token 文件 |
| **布局** | 栅格、断点、容器宽度 | 进 token 文件，页面引用 |
| **内容与文案** | 页面上的文字 | 与 token 无关，单独处理 |

**最容易犯的错：** 把「风格」当成一次性样式，直接写死在某个页面里。结果是第二页的风格要靠重新描述，必然漂移。

## 二、判定与路由

进入后先判定走哪条路：

| 情形 | 判定信号 | 走哪条 |
|---|---|---|
| **A. 有参考物** | 给了网页 URL、设计稿链接、截图 | 完整流程：抓取 → 提取 → 落 token → 生成页面 |
| **B. 只有描述** | 「要一个科技感、蓝色调的后台」 | 先按描述生成 token **草案**，明确标注为「草案·未经参考物校准」，再生成页面 |
| **C. 已有 token 文件** | 用户指向一个已存在的 token 文件 | 跳过提取，直接校验该文件 → 生成页面 |
| **D. 只要 token** | 「只要设计规范，先别写页面」 | 走到第四步即停，不生成页面代码 |

**降级判定：** 用户只要一个单页、且明确说「随便好看就行」→ 走 B 的简化版，token 只写最小集合（见第四节规则 3），不要生成 9 大章节的完整文档。

## 三、工作流

1. **取参考。** URL 用 `scripts/fetch-page-css.py <url>` 抓取页面与样式，产出候选值清单；截图直接读取图片。
   脚本会在抓不到编码或解码失败时于 stderr 打**编码警告**；看到警告即以截图为准，不要照抄可能被吃掉的候选值。
   抓取失败按第六节降级。
2. **提取候选。** 从候选值中筛出：主色/强调色、中性色阶、背景与前景、字体族、字号阶梯、间距节奏、圆角、阴影。
3. **落成 token 文件。** 写到项目内的 `design-tokens.css`（或用户指定路径），变量命名见 `@references/token-spec.md`。
   **这是必须落地的文件，不是对话里的一段话。**
4. **自检 token。** 逐项核对规则 3 的最小集合是否齐全；不齐就标「未提供」并补足中性默认值，**不得留空**。
5. **生成页面代码。** 所有颜色、字号、间距、圆角、阴影一律 `var(--xxx)` 引用，禁止内联硬编码。
6. **多页一致性收口。** 生成第 2 个及以后的页面时，**先读已有的 token 文件**，只增量补充 token，不重写。
7. **回报。** 说明 token 文件路径、覆盖了哪几类、哪些值是推断的。

## 四、核心规则

**规则 1：没有 token 文件，禁止生成页面（红线）**

- 触发条件：任何时候要产出页面代码。
- 硬性动作：必须先存在 token 文件（磁盘文件，非对话内容）。**禁止**跳过这一步直接写页面。
- 正例：✓ 先写 `design-tokens.css`，再写 `index.html` 并在其中 `@import`。
- 反例：✗ 「根据这个设计，我直接给你写了页面」——直接在 HTML 里写 `#5B8DEF`，第二页必然对不上。
- 降级路径：用户明确拒绝生成文件（如在受限环境），则在对话中输出完整 token 文本并在开头标注「未落盘，请手动保存后再生成页面，否则多页风格会漂移」。
- **本条优先于第五节的所有格式要求。**

**规则 2：色值必须来自参考物，不得凭印象补全**

- 触发条件：填写任何颜色值。
- 硬性动作：色值必须来自抓取结果、截图中实际取到的像素，或用户明确给出的值。**禁止**用「科技感一般用蓝色」这类推断充当主色。
- 正例：✓ 「主色 `#5B8DEF`，来源：抓取到的 `.btn-primary` 背景色。」
- 反例：✗ 「主色用 `#1677FF`，这是常见的科技蓝。」（参考物里根本没有这个色）
- 降级路径：抓不到就用中性灰阶打底，主色标「未提供，暂用 `#3B82F6` 占位，请替换」。占位值必须显式标注。

**规则 3：token 必须覆盖最小集合**

- 触发条件：写完 token 文件准备生成页面前。
- 硬性动作：以下 8 项缺一不可，缺失项用中性默认值补齐并标注：
  `主色` `强调/成功/警告/错误色` `中性色阶（至少 5 级）` `背景色` `前景/正文色` `字体族` `字号阶梯（至少 4 级）` `间距节奏（至少 4 级）`。
  `圆角` 与 `阴影` 为建议项，可标「未提供」。
- 正例：✓ 8 项齐全，另加圆角 3 级、阴影 2 级。
- 反例：✗ 只写了主色和一个背景色就开始生成页面。
- 降级路径：参考物信息量不足（如纯文字站点）→ 按最小集合补齐中性默认值，在文件头注释中列出哪些是补的。

**规则 4：页面只引用，不内联**

- 触发条件：写任何一处样式。
- 硬性动作：颜色/字号/间距/圆角/阴影一律写 `var(--token-name)`。**禁止**出现未经 token 定义的裸色值。
- 正例：✓ `background: var(--color-primary);`
- 反例：✗ `background: #5B8DEF;`（哪怕这个值等于 token 的值也不行——改 token 时这处不会跟着变）
- 例外：透明色 `transparent`、纯白纯黑 `#fff`/`#000` 允许直接写。
- 降级路径：需要 token 里没有的值 → **先补 token 再写样式**，不许就地写死。

**规则 5：多页只增不重写**

- 触发条件：生成第 2 个及以后的页面。
- 硬性动作：先读已有 token 文件，缺什么补什么。**禁止**重新生成一份新的 token 文件覆盖旧的。
- 正例：✓ 「已读取现有 token，新增了 `--space-7`，其余沿用。」
- 反例：✗ 「我为你重新整理了一份更完整的 token 文件。」（旧页面的引用会指向被删掉的变量）
- 降级路径：确实需要重构命名 → 保留旧变量名作为别名指向新变量，不删除旧名。

**规则 6：不搬运受保护的资产**

- 触发条件：参考物里出现 logo、插画、品牌专属图形、付费字体。
- 硬性动作：**禁止**将其写入产出物。字体若为非开源字体，改用系统字体栈并在 token 中注明替代关系。
- 正例：✓ 「原站使用 XXX Sans（商业授权），已替换为系统无衬线字体栈，视觉接近。」
- 反例：✗ 直接引用原站的字体 CDN 链接。
- 降级路径：用户坚持要同款字体 → 提示需自行购买授权，token 里先留字体名占位。

## 五、输出格式

**token 文件（必须落盘）** 骨架：

```css
/* design-tokens.css —— 由「晓得·设计解剖」生成 */
/* 来源：<参考物 URL 或截图路径>   生成日期：<YYYY-MM-DD> */
/* 标注说明：[推断] 表示参考物中未明确出现、由默认值补齐 */

:root {
  /* 1. 主色与语义色 */
  --color-primary: #5B8DEF;
  --color-success: #2FA84F;
  --color-warning: #E8A33D;
  --color-danger:  #D93F3F;

  /* 2. 中性色阶 */
  --gray-50:  #F7F8FA;
  --gray-100: #EDEFF2;
  --gray-300: #C9CED6;
  --gray-600: #6B7280;
  --gray-900: #1F2329;

  /* 3. 背景与前景 */
  --bg-base:    #FFFFFF;
  --bg-subtle:  var(--gray-50);
  --fg-base:    var(--gray-900);
  --fg-muted:   var(--gray-600);

  /* 4. 字体与字号阶梯 */
  --font-sans: -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
  --text-xs: 12px;  --text-sm: 14px;
  --text-md: 16px;  --text-lg: 20px;  --text-xl: 28px;

  /* 5. 间距节奏 */
  --space-1: 4px;  --space-2: 8px;   --space-3: 12px;
  --space-4: 16px; --space-6: 24px;  --space-8: 32px;

  /* 6. 圆角与阴影（建议项） */
  --radius-sm: 4px; --radius-md: 8px; --radius-lg: 16px;
  --shadow-1: 0 1px 2px rgba(0,0,0,.06);
  --shadow-2: 0 4px 12px rgba(0,0,0,.10);
}
```

完整字段规范（含命名约定、分级数量、断点与栅格）见 `@references/token-spec.md`。

**反模式禁止清单：**

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | 跳过 token 直接写页面 | 第二页必漂移，这是本技能存在的唯一理由 |
| 2 | token 只存在于对话里，不落盘 | 换一次对话就没了 |
| 3 | 页面里出现裸色值 | 改 token 时改不动，一致性形同虚设 |
| 4 | 用「科技感/高级感」推断主色 | 用户拿到的不是参考物的风格，是你的想象 |
| 5 | 生成第二页时重写 token | 旧页面引用断链 |
| 6 | 把 8 项最小集合写成 20 项 | token 越长，生成时越容易被忽略，风格反而散 |
| 7 | 直接引用商业字体 CDN | 授权风险 |
| 8 | 输出 token 后不回报哪些是推断的 | 用户无法判断可信度 |

## 六、防幻觉（硬约束，优先级最高）

**本节优先于以上所有格式与流程要求。**

1. **每个数值必须可溯源。** 色值、字号、间距必须来自抓取结果、截图像素或用户给定值。
   **禁止**为了让 token 文件"看起来完整"而凭空补数值。
2. **推断值必须显式标注。** 参考物里没有、由你补的，一律在注释里标 `[推断]` 或 `未提供`。
   **禁止**用「通常」「一般」「建议」这类词掩盖推断。
3. **抓不到就说抓不到。** URL 访问失败、页面是纯前端渲染、截图模糊无法取色 → 明确说明原因并按规则 2 降级。
   **禁止**假装抓到了然后给一套"合理"的配色。
4. **不猜品牌与产品名。** 参考站是哪个品牌就写哪个，看不出来就写「未知站点」。
5. **区分三种来源并说明：** 用户提供的 / 我从参考物提取的（附具体位置）/ 我推断的（标注 [推断]）。
6. **不确定就直说不确定。** 「这个截图分辨率太低，主色我只能取到近似值 `#5B8DEF`（±2），建议确认」是合格输出。

## 七、按需知识

只在遇到对应问题时读取，不要一次全读：

- **`@references/token-spec.md` §八「自检清单」—— 产出 token 文件后必跑**（逐条过一遍再交付）
- **`@references/extraction-guide.md` §五「常见坑」—— 动手取候选值前必读**（取色/解码/标注三类坑）
- token 的完整字段规范、命名约定、分级数量、中性色阶、字号阶梯、断点栅格、字体族降级栈、暗色主题
  → `@references/token-spec.md` §一~§七
- 从网页/截图/文字描述三种来源提取候选值的方法、脚本参数与结果解读、标注方式
  → `@references/extraction-guide.md` §一~§四

## 八、完成判据

**算做完：** token 文件已落盘 + 8 项最小集合齐全（缺项已标 [推断]）+ 页面代码中颜色/字号/间距/圆角/阴影全部走 `var()` + 已回报哪些值是推断的。

**不自动做：** 不自动生成设计规范说明文档（除非用户要）；不自动开始做交互逻辑与后端；不自动替换用户已有页面的样式（除非明确要求迁移）。

## 九、降级与跨轮次

- **抓取失败：** URL 打不开或被反爬 → 依次尝试：请用户提供截图 → 请用户粘贴关键元素的色值 → 按 B 路径生成标注为「草案」的 token。**禁止**在没有任何参考信息时静默生成一套完整配色。
- **纯前端渲染页面：** 脚本抓不到样式 → 明确告知，请用户提供截图或手动复制关键元素色值。
- **信息不全时的唯一降级路径：** 假设 + 就地标注 + 继续。既不要连环追问（最多问一次，且要给出默认值让用户可直接使用），也不要交白卷。
- **用户嫌 token 太长：** 可只输出 8 项最小集合，但必须说明「圆角与阴影未定义，生成时按 0 处理」。
- **跨轮次：** 后续对话中提到「再加一个页面」时，默认读取本项目已有的 token 文件，不再询问参考物。
