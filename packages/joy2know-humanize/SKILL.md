# 晓得·凡人腔调

把中文论述文里的机器腔调改掉：只动规则清单里明确命中的地方，其余逐字保留。

**这个技能不做润色。** 润色是「读着更好」，本技能是「读着不像模型」。两者的判断依据完全不同：前者靠语感，后者靠触发标记。混淆这两件事，就会把作者的个性连同腔调一起抹平。

---

## 一、先分清：三个「不」

| 不做 | 因为 |
|---|---|
| 不润色 | 没有命中任何规则的句子必须逐字保留。觉得它「可以更好」不构成改动理由。 |
| 不改结构 | 标题层级、章节顺序、段落数量与顺序、列表、表格、引用、代码块的位置一律不动。 |
| 不补内容 | 不能新增姓名、数字、日期、引语、来源、因果或任何原文没写的细节；也不能删掉观点、结论、限定词。 |

**白名单原则。** 允许的改动只有落在规则清单里的那些。指不出对应规则号的改动，一律撤销、恢复原文。

**信息守恒的判定办法。** 改写后每个实词都要能在原文里指出出处。指不出来就是新增，必须撤销。把「可能提升」写成「提升」是篡改判断强度，不算去腔调。

---

## 二、判定路由

开工前先问三件事，答案决定了后面怎么做。

**1. 这是不是论述文？**

本技能只做中文论述文（评论、复盘、分析、说明、技术文章）。下面这些**不要动手**：

- 小说、散文、诗歌等文学体裁 → 停手，风格是作者的一部分
- 操作步骤、法规条目、配置清单 → 停手，整齐是它的要求
- 整段是对话或引语 → 跳过该段
- 非中文为主的段落 → 跳过

**2. 有没有风格参考文档？**

同目录下若有写作风格指南、语言特征分析一类的产物，**先读它再改**，把它的句长分布、标点习惯、用词偏好作为判断依据。

**风格文档与规则表冲突时，以风格文档为准。** 那是目标作者的真实写法，不是机器腔调——比如某作者本来就爱用破折号，就不该按 R06 删掉。

**3. 能不能跑脚本？**

能跑 → 按第四节四步走，定位与验收都交给脚本。
不能跑 → 直接进第十节的降级路径，用规则表和完成判据人工过一遍。

---

## 三、三条铁律

三条都写在门禁里，是可执行的判据，不是提醒。

1. **白名单** —— 只改命中处，改动控制在解决该问题所需的最小范围，不顺便润色相邻文字
2. **信息守恒** —— 数字、日期、引语、书名号、英文串、专有名词一个都不增删；限定词计数不变
3. **结构守恒** —— 标题层级序列、段落数、代码块、表格、引用、列表项数完全一致

---

## 四、工作流（四步）

### 第 0 步 · 摸清稿件

```bash
python3 scripts/scan.py 稿件.md --triage
```

输出**豁免区地图**：哪些行是代码、引用、表格、列表，哪些段落是引语。豁免不是遗漏，是保护——这些地方改了会散架。

### 第 1 步 · 定位命中，先看再改

```bash
python3 scripts/scan.py 稿件.md
python3 scripts/scan.py 稿件.md --audit 20      # 随机抽 20 条，连上下文一起看
```

**命中不等于必改。** 算子的覆盖范围总会比规则名宽一点，而频率数字本身不提示这件事。所以先抽样看命中实例长什么样，确认是这条规则要治的病，再动手；不是的，跳过并在交付说明里写明。

### 第 2 步 · 改

分两路走，顺序不能反：

**机械替换先做。** 规则表里标了机械替换的条目不需要读懂句意：

```bash
python3 scripts/fix.py 稿件.md --out 改后.md              # 先干跑，看它要改什么
python3 scripts/fix.py 稿件.md --out 改后.md --write      # 确认后再落文件
```

覆盖 R01 翻案腔、R02 段首补回指、R04 提示语冒号、R05 序数词小标题、R07 起手式、R12 译文句式、R13 时代背景起手。这部分零 token、零漂移、可回滚。

**其余留给判断。** 段首零回指要看上下文、破折号要看是揭晓还是插入、拟人喻体要换说法、相邻句同构要打散句法、顿号过密要看是否拥挤——这些脚本做不了，硬做只会把文章改坏。逐条按 @references/rules.md 的「改法」处理。

### 第 3 步 · 过门禁，不过不许交稿

```bash
python3 scripts/guard.py --before 原稿.md --after 改后.md
```

**退出码非 0 就是没通过，不许交稿。** 四道检查：

| 检查 | 抓什么 |
|---|---|
| 硬守恒 | 数字、引语、书名号、链接、英文串被增删 |
| 强度守恒 | 「可能／通常／据说」这类限定词计数变了 |
| 结构守恒 | 标题层级、段落数、列表项数等被动了 |
| 越界改动 | 有改动，但指不出对应哪条规则——**最难自查的那条** |

越界改动按**句子**判，不按行判：同一行里常有两三句话，按行判的话顺手润色另一句也能过。判定规则是「每处改动都必须落在一个有规则命中的句子里」。

没过就修：越界改动撤销恢复原文，丢掉的元素补回，结构变了说明改了框架、回滚重来。改完再跑一次。

## 五、规则表

13 条规则，分三级。逐条的触发标记、改法、不改的情况、正反例见 @references/rules.md。

| 编号 | 规则 | 级别 | 证据 | 机械可替换 |
|---|---|---|---|---|
| R01 | 翻案腔（对举结构） | P0 | 强 | 是 |
| R02 | 段首零回指评论 | P0 | 强 | 部分 |
| R03 | 空转句引出列表 | P0 | 强 | 否 |
| R10 | 拟人化喻体 | P0 | 强 | 否 |
| R04 | 提示语引出的冒号 | P1 | 强 | 部分 |
| R05 | 序数词当小标题 | P1 | 强 | 是 |
| R07 | 起手式（说白了／说穿了） | P1 | 强 | 是 |
| R09 | 相邻句结构同款 | P1 | 中 | 否 |
| R11 | 概括词盖掉已有数据 | P1 | 反向 | 否 |
| R12 | 译文句式（五种） | P1 | 中 | 部分 |
| R06 | 破折号滥用 | P2 | 不稳定 | 否 |
| R08 | 顿号罗列过密 | P2 | 弱 | 否 |
| R13 | 时代背景起手 | P2 | 本版新增 | 部分 |

**优先级含义。** P0 改一条赚一条；P1 不改就还是模板；P2 证据偏弱，看整篇密度决定，不逐处判死。

**证据等级不是装饰。** 「强」表示与人类文本的区分力约 3 倍以上；「反向」表示人类侧反而更高，**只能用来禁止往反方向改**，不能当作删除理由；「不稳定」表示组间或跨模型差异过大，降为视情况；「本版新增」表示尚无对照数据，属可选规则——用户说「只改有据可查的」时整条跳过。量级口径与来源见 @references/baseline.md。

## 六、不可改清单

这张表和规则表一样是硬约束。列在里面的特征**看着像机器腔调，实测站不住**，不能据此改文字。完整清单见 @references/not-rules.md，最常被误改的四条：

- **句长、段长的参差度** —— 为了「制造节奏」调句长或拆段落，等于按一个不存在的特征改稿
- **设问句** —— 正文设问人类远多于生成文本，按「删设问」改会越改越不像人写
- **比喻本身与比喻独立成段** —— 人类用比喻的频率是生成文本的数倍，只有「理想化职业人格」这一种喻体（R10）才处理
- **名词化结构** —— 公开对照数据是反向的（人类侧更多），本版不收。只在「原文已有具体数据」时禁止用概括词盖掉（R11）

**还有一层：** 主观上觉得某句生硬、不像中文，不构成改动理由。只有能在规则表里指出触发标记的才允许动。

## 七、脚本

四个脚本，纯标准库，零第三方依赖。三个只读，一个只写。

| 脚本 | 读写 | 作用 |
|---|---|---|
| `scan.py` | 只读 | 定位命中、输出豁免区地图、抽样审计 |
| `guard.py` | 只读 | 改写前后门禁，四道检查 |
| `selftest.py` | 只读 | 规则表自检：正例必中、反例必不中 |
| `fix.py` | **唯一写盘** | 机械替换；默认干跑，必须显式 `--write` |

```bash
python3 scripts/scan.py 稿件.md                  # 命中清单
python3 scripts/scan.py 稿件.md --triage         # 豁免区地图
python3 scripts/scan.py 稿件.md --audit 20       # 抽样检视
python3 scripts/scan.py 稿件.md --json           # 机器可读
python3 scripts/fix.py 稿件.md --out 改后.md [--write]
python3 scripts/guard.py --before 原稿.md --after 改后.md
python3 scripts/selftest.py                      # 改过规则表就跑
```

**规则表只有一份。** 所有脚本从 `scripts/rules.py` 读规则，@references/rules.md 与 @references/not-rules.md 由它生成。改规则只改 `rules.py`，然后跑 `selftest.py` 验正反例，再跑 `scan.py --render` 重生成两份文档——不要手改 references 下那两份。

## 八、输出格式

交付三样，缺一不可：

**1. 改后全文。** 直接给，不要分段解释。

**2. 变更清单。** 一行一处：

```
行 24  R01 翻案腔     原：真正的壁垒不是技术，而是认知。
                      改：真正的壁垒是认知。
行 30  R02 段首零回指  原：更重要的是，口径这件事始终没有人负责。
                      改：这一点更重要，口径这件事始终没有人负责。
```

**3. 门禁结论。** 贴 `guard.py` 的判定结果，包括残留命中及其跳过理由。

用户没问就不解释过程。问了再说明哪条为什么这么改。

## 九、完成判据

逐项过，任一项不过就回去改：

- [ ] 每一处改动都能指回规则表里的具体编号。指不出的已撤销
- [ ] 改动控制在解决命中问题所需的最小范围，没有顺便润色相邻文字
- [ ] 未命中规则的句子逐字保留
- [ ] 标题层级、段落数量与顺序、列表、表格、引用、代码块位置完全一致
- [ ] 数字、日期、引语、书名号、英文串、专有名词一个都没增删
- [ ] 限定词与让步（可能、通常、据说、在某些情况下）计数不变，判断强度没被加重
- [ ] `guard.py` 四道检查全过，退出码为 0
- [ ] 残留命中已逐条说明：属于「不改的情况」，还是本轮决定不动
- [ ] 没有按「不可改清单」里的特征改过任何一处
- [ ] 没有为了「像人写的」强加人称、口语或短段落——体裁要求优先

## 十、降级路径

**跑不了脚本时（没有 python、或用户只要结果不要过程）：**

1. 读 @references/rules.md，按 P0 → P1 → P2 的顺序人工扫一遍
2. 扫之前先在心里划出豁免区：代码、引用、表格、列表、整段引语
3. 改完对一遍第九节的完成判据，逐条自查
4. **在输出里说明这次没过门禁**，让用户知道守恒与越界那两道检查没跑

**用户说「只改有据可查的」时：** 跳过证据等级为「本版新增」的规则（R13），只做「强」「中」「反向」三类。

**用户要的是润色、扩写、缩写或改结构时：** 本技能不接。说明边界，让用户另找工具——按本技能的规则去润色，会把文章改得比原来更糟。

**用户给了风格参考文档时：** 那份文档优先于全部规则。规则表管的是「模型写的」，风格文档管的是「你写的」，后者说了算。
