## 四、门 3 · 合理性结论

- **规则是否自洽**：✅ 无互相打架。规则 1（卖点是好处）与规则 2（定位要过差异化这一问）是两级：
  前者管**单条卖点的表述**，后者管**整体的区分度**；规则 5（渠道）独立于前三者。
  边界成对写清 —— agent 明写「你交付的是『讲什么』，不是『怎么讲』」，用下一环的活来界定自己。
- **推断是否标注为推断**：✅ 无竞品信息时差异化必须标 `【假设-需验证】`；产出格式末尾专设「假设与待验证」一节。
- **错误提示是否可指导下一步**：✅ 降级路径明确（差异化填不出 → 如实说 + 给换人群/换场景/换交付方式三个可选动作）。
- **边界是否优雅**：✅ §六 覆盖五类边界（不做选题/文案、不承诺效果、不替用户判断产品该不该做、不代人转交）。
- **零依赖是否守住**：✅ 结构性成立。
- **值来源是否可追溯**：✅ 版本号 1.0.0 三处一致；头像真源在仓库根 `avatars/`。
- **⚠️ 渠道四项打分的权重**：四项（人群聚集 / 形态匹配 / 冷启动成本 / 可持续产出）**等权相加**，未设权重 ——
  这是刻意选择（避免用「我们觉得重要」去掩盖没有依据的判断），但等权本身也是一种假设，见弱项 W1。

## 六、未覆盖项 / 已知缺陷 / 待办

**未覆盖项**：

1. **定位实际质量未评估**：本轮只验结构与规则齐备，不验内容质量（参数是否真被翻译成好处、
   「和谁不一样」第三空是否填得住、渠道排序是否有依据）。需真实跑一轮定位才能评估 —— **最大未覆盖面**。
2. **规则 3 的「主动收集反对意见」是否真会被执行**：属生成行为，自动化只能确认规则文本存在。
3. **平台侧真实上传 / 解析 / 审核未实测**。
4. **`categoryId` 取 `05-MarketingGrowth` 是推断值**：平台是否认可**未经实证**。
5. **`skills: []` 的专家包在平台侧如何展示未实测**。

**已知弱项**：

- **W1 · 渠道四项等权相加是自定假设**：等权回避了「拍权重」，但等权本身没有依据。
  若真实使用中出现「某一项明显更重」的品类，应显式改为加权并说明理由，而不是靠感觉调总分。
- **W2 · 无品类差异化案例库**：规则 2 给了写法和降级路径，但没有跨品类的正例库。
  这是**下一个版本的增值点**（需求真实、成本可控）。

**待办**：

- 出真头像 → 覆盖同名文件 → 重跑 `node scripts/build.mjs joy2know-positioning`。
- 真跑一轮定位，评估未覆盖项 1、2。
- 首次提交后回填 `release.config.json` 的 `submitted`。
