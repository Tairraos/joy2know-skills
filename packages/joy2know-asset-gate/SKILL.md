# 资产包门禁

**检测不是「跑一遍没报错」。** 四道门依次过，每道门留下**可复核的证据**（命令 + 样本 + 输出要点）。

四道门靠自觉一定会放水，所以本技能的核心不是「讲道理」，
而是把**放水的信号灯做成可执行判据** —— 报告写得再漂亮，不合规照样红灯。

---

## 〇、先用门禁

```bash
# 查一份检测报告是否合规（最常用）
python3 scripts/gatecheck.py --report packages/包名/包名.md
python3 scripts/gatecheck.py --dir packages/包名

# 反向自检这个校验器本身
python3 scripts/gatecheck.py --selftest
```

**退出码**：0 全过 / 1 有硬缺陷 / 2 用法错或找不到报告。

⚠️ `--selftest` 里有一组**篡改判据本身**的用例（收窄状态集合、关掉未覆盖项判据、
清空放水话术表），断言目标文案必须跟着翻转。
**没有这组，你无法证明「它报红」是因为内容有问题，而不是因为它天生爱报红。**

---

## 一、四道门

### 门 1 · 功能测试（真跑）

- **每条对外能力都要真跑一次**，给真实命令与真实输出。
- **每条能力至少两个样本**：一个正常、一个边界（空输入 / 缺文件 / 中文英文混排 / 超长 / 不合规格式）。
- **降级路径单独测**：声明「缺 X 就降级」的，把 X 藏起来再跑一次，确认不崩且提示正确。
- ⛔ **禁止用「读代码推断它能跑」代替运行。没跑过的一律记入「未覆盖项」。**

### 门 2 · 功能完整性（对照承诺）

把文档里的**能力承诺逐条摘出来**与实现对照，逐条标 **有 / 无 / 部分**。

重点抓 **「文档写了、实现没做」** —— 这是真实发生过的事故类型。
兜底口径两条：**文档写了的能力，实现里必须有；实现里有的能力，文档里必须写。**

### 门 3 · 合理性

| 检查 | 要求 |
|---|---|
| 规则自洽 | 两条规则不能互相打架；打架了要给出**判断标准**，不能只说「不要这样」 |
| 推断要标推断 | 靠启发式猜出来的结论要显式标记，不能当事实写 |
| 报错可指导 | 说清「发生了什么 + 你可以怎么做」，不只抛堆栈 |
| 边界优雅 | 空数据、缺文件、旧格式、重复记录 → 给提示而不是崩或静默 |
| 零依赖是否守住 | 声明「零第三方依赖」就查有没有 import 外部包 |
| 值来源可追溯 | 外部取值要记来源，缺就标「未提供」，**不许凭空补值** |

### 门 4 · 测试真实性（防放水）★ 最容易糊弄的一道

见下节。**四道门跑完，报告必须能回答一句话**：
**「这条能力如果坏掉，是哪一步会亮红灯？」** 答不上来的能力，就是没人看着的能力。

## 二、假测试的九种形态（逐条自查，中一条即未通过）

| # | 形态 | 怎么破 |
|---|---|---|
| 1 | 只跑 happy path | 每条能力必须有边界样本 |
| 2 | 只看「没报错 / 退出码 0」，不看输出对不对 | 必须核对输出内容本身 |
| 3 | 把「文档写了」当成「已验证」 | 证据必须是运行的输出 |
| 4 | 自造理想样本（比真实产物干净） | 样本贴近真实格式 |
| 5 | 跳过失败项、不记录 | 失败与未测项写进「未覆盖项」 |
| 6 | 修完只测修好的那条 | 必须**回归**：原有能力全跑一遍 |
| 7 | 造错样本只造了会被抓的那种 | 必须做**反向验证** |
| 8 | 退出码取自管道末端 | `cmd \| tail -4; echo $?` 的 `$?` 是 `tail` 的，恒 0。**取退出码不要经过管道** |
| 9 | **恒真断言**（拿一个纯函数与它自己比较） | `a === b` 两边同一个表达式 → 恒成立，且没调真正的函数，**被测对象整个坏掉也照样报绿** |

第 9 种的破法：**自检必须走真实代码路径，不许在测试里重算被测逻辑**；
每条新判据配一条反向对照 —— **造一个坏实现，断言该判据判它失败**。

---

## 三、反向验证（修校验器 / 修 bug 之后必做）

**做法**：篡改**检查逻辑本身**，断言**目标文案的有 / 无会反转**。不能只看退出码。

三个要求：

1. **反向样本每项只错一处**，且必须**回读确认**样本真的错在那一处。
2. 同一套用例**跑改前 / 改后两版**。
3. **判据必须锚定到具体那一行** —— 两段式匹配会在别处命中同串，把篡改喂绿。

报「未翻转」或「全翻转」时，**先怀疑验证器本身**。

### ⚠️ 跑反向验证前，先让干净样本全绿

否则会把**环境噪声**当成包的缺陷来修。三条真实踩坑：

1. **副本目录名必须保持包名** —— 校验器常按目录名校 `name`，放成 `/tmp/x/baseline/`
   会连带报两条**假红灯**。改用 `<样本名>/<包名>/` 双层结构。
2. **头像等真源的回退路径是「父目录的父目录」** —— 软链放在样本目录里**无效**。
3. **别用行首锚定抓红灯** —— 某些输出行带**两个前导空格**，
   `grep -E "^\[XX\]"` 会**静默输出空结果**，看起来像「全部通过」
   —— 等同于「一项没查却报绿」。

## 四、检测报告的结构

位置 `packages/<包名>/<包名>.md`（与包目录同名）。**不进 zip，进 git。**

**头部四行必须列表格式**（`- **对应版本**：…`）—— 写成 `>` 引用块构建脚本判不出：

```md
- **对应版本**：1.0.0
- **检测状态**：✅ 已通过
- **最后检测**：2026-10-12
- **检测方式**：功能测试 + 完整性对照 + 合理性检查 + 反向验证
```

**状态只允许四选一**（写「基本通过」「大概没问题」等同「未检测」）：

| 状态 | 含义 | 能否打包 |
|---|---|---|
| `✅ 已通过` | 四道门全过，无遗留未覆盖项 | 可以 |
| `⚠️ 有条件通过` | 四道门已过，但有明确的未覆盖项 | 可以，未覆盖项要写清 |
| `⛔ 未检测` | 还没测，或只生成了骨架 | 构建告警；`--strict` 失败 |
| `❌ 未通过` | 有硬缺陷未修完 | 同上 |

**正文七节**：一、包内文件（**从磁盘枚举，不手写**）／二、能力清单与验证结果／
三、门 2 完整性对照／四、门 3 合理性结论／五、门 4 测试真实性自评／
六、未覆盖项 / 已知缺陷 / 待办／七、检测履历。

### 复用规则（这份文档的全部意义）

**下次检测先读它，不要从头再测。**

- **可以信任**：已验证 + 对应版本未变 + 相关文件未改的能力
  （构建会检查报告是否比源码旧）。
- **必须重测**：本次改动碰到的能力 + 相邻能力（回归）+ 文档里列出的未覆盖项。
- **顺手补漏**：每次至少消掉一条未覆盖项，让它越来越薄。
- 每次都**追加一行履历**并更新头部四行。

## 五、放水的信号灯（`gatecheck.py` 就是这七条的判据）

出现任一，报告即不合格：

1. **「未覆盖项」一栏是空的** —— 没有任何一次检测能覆盖 100%，**空 = 没认真写**。
2. 头部四行缺一行，或写成引用块（构建判不出，**静默失效**）。
3. 检测状态写了四选一以外的值。
4. 声称「✅ 已通过」却没有反向验证记录。
5. 证据只有命令没有输出实据。
6. 结论写「应该没问题 / 大概率可以」。
7. 检测履历只有一行 —— 报告在复用中悄悄过期。

⚠️ **第 5 条的判法**：只认**实数实据**（`退出码`、`14/15`、`共执行 21`、`返回 0`），
不能只匹配「输出」「要点」这类**元叙述词** —— 「只贴命令不贴输出要点」这句话本身
就含「输出要点」，会把没贴证据的报告判成有证据。

## 六、本技能自身的施工留痕

开发 `gatecheck.py` 时，自检先后抓出四个真缺陷，全部是**判据与文案不一致**的类型：

| 缺陷 | 症状 |
|---|---|
| `Pattern.search(text, re.M)` | `re.M` 被当成 `pos=8`，**静默返回空** —— 该小节永远「找不到」 |
| 反向验证判据全文搜 | 头部「检测方式」字段天然含该词 → 每份报告自动通过，判据形同虚设 |
| 输出实据判据全文搜 | 第五节的 `exit=1` 把「第二节只贴命令」盖掉 → 必须**按小节**判 |
| 断言写「输出要点」、判据写「输出实据」 | 用例匹配不上，**测的是文案不是判据** |

> 共同点：**都不报错，只是静默地不生效**。
> 这就是为什么「跑通」不等于「在查」—— 必须靠反向对照与文案对齐来暴露。

---

## 七、本技能的边界

- **只管检测与报告**，不管字段取值（→ 「资产字段规范」）、不管内容写作、不管驳回处置。
- **`gatecheck.py` 校验的是报告形式与放水信号，不是技术正确性** ——
  一份形式完美但结论错误的报告，它拦不住。技术正确性由四道门里的人负责。
