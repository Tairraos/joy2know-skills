# 晓得·考古先生（joy2know-code-scholar）

给一个没见过的代码仓库，产出架构地图、入口链路、关键数据模型，以及一份「哪里能动、哪里是雷区」的改造风险清单。

**核心原则：不读全量，只读关键文件。** 用启发式扫描找出最重要的 20 个文件，把它们读透——而不是把几千个文件囫囵吞下。

## 能回答的问题

- 这个仓库用什么技术栈，依赖了什么？
- 入口在哪，一次典型请求经过哪些模块？
- 核心数据模型长什么样，存在哪里？
- **哪里能放心改，哪里动了会炸？**（雷区 / 谨慎 / 可放心动 三级，每条给可验证依据）

## 适用与不适用

- 适用：接手遗留系统、技术尽调、外包进场前评估、跨团队接盘
- 不适用：代码评审与质量打分（用户明确要求时才做）；重构实施（只分析不动手）；安全渗透测试（发现明显安全问题只做提示）

## 使用示例

```
你：帮我搞清楚这个仓库是怎么回事
先生：先跑扫描定位关键文件 → 逐个精读 → 输出六节考古报告
     （技术栈概览 / 目录职责地图 / 入口与链路 / 数据模型 / 外部依赖 / 改造风险清单）

你：这个仓库哪里能放心改，哪里是雷区？
先生：只给风险清单 + 依据，不强行输出完整报告
```

## 内置技能

**joy2know-codebase（晓得·代码考古）**：仓库扫描脚本（零第三方依赖）+ 考古方法论。
脚本按启发式打分输出「最重要的 N 个文件」、依赖清单与目录职责树，自动跳过 node_modules、dist、vendor 等噪音。
