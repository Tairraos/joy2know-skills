## 四、门 3 · 合理性结论

- **规则是否自洽**：**本轮发现并修掉一处不自洽的表述边界** —— 规则 1 红线写「禁止把修改时间做成检索维度」，
  规则 6 又要求「按生成时间邻近推断批次」，两条表面打架。现已在规则 1 补上判断标准：
  **文件属性可以作「推断线索」，不可以作「检索滤镜」**（判断依据是「产出的是创作维度还是文件属性」）。
  → **本轮另发现并修掉一处结构缺陷**：核心规则小节顺序原为 1→2→3→4→5→**7→6**（规则 7 排在规则 6 前），
  已调整为 5→6→7。属排版缺陷，不影响行为，**因此不抬版本号**（1.2.0 尚未上线）。
- **推断是否标注为推断**：✅ 批次全部带 `[推断]`，依据记 `filename+time` / `filename-only`。
- **错误提示是否可指导下一步**：✅ 命中 0 条时会区分「台账里确实没有」与「有但被废片过滤掉了」
  （本轮修过两次：一次是提示语在用户已显式指定 `--scrap` 时仍出现，一次是关键词未命中时误报废片提示）。
- **边界是否优雅**：✅ 空台账、不存在的台账、旧格式台账、重复记录四种边界均已实测（见二）。
- **零依赖是否守住**：✅ 只 import 标准库；外部命令仅可选 `ffprobe`。
- **值来源是否可追溯**：✅ `meta_source` 四态（`embedded` / `sidecar` / `user` / `none`）。
  **本轮修掉一处自造缺陷**：`set` 原本无条件把 `meta_source` 改写成 `user`，导致「只补一个 `role`」
  就把「提示词来自图内元数据」这个事实抹掉、`stats` 的来源分布假性归零。现改为只有真改 `--prompt`
  才改写，人工介入只记 `flags: user-edited`。
- **另一处自造缺陷（已修）**：批次编号原先拿「桶总数」当序号，导致三条同批素材全被标成 `#2`；
  现按桶序号分配。

## 六、未覆盖项 / 已知缺陷 / 待办

**未覆盖项**（下次检测优先消掉这些）：

1. **HTML 看板的前端交互**：`render` 产物的结构、内联数据、缩略图路径已核（7/7 可达），
   但**筛选器 / 重置按钮 / 筛选后的条数变化没有在真实浏览器里点过**，也没有自动化断言。
2. **`ffprobe` 两个分支都没实测**：本机装了它时视频分辨率/时长的实际取值，以及**没装时的降级提示**
   （「留空、不报错」）均未验证。视频 `duration` 本轮的值来自分镜清单，不是 `ffprobe`。
3. **三个降级路径未造样本**：`--keep-raw-meta` 落原文、罕见封装导致分辨率解析失败、文件名对不上分镜清单。
4. **两个开关未跑**：`--recursive`（递归扫描子目录）、`--no-batch`（关闭批次推断）。
5. **`suspect-rename`**（文件改名后的提示）未造样本验证。
6. **规模与性能未测**：样本量 7 条。上千文件时的扫描耗时、台账体积未测。
7. **平台兼容性未测**：只在 macOS + Python 3.13 上跑过（脚本用标准库，理论上跨平台，但未实测）。

**已知缺陷**：

- 无已知功能性缺陷。本轮修掉的 2 个 bug（CSV 增量、废片默认过滤）+ 2 处自造缺陷
  （来源标记污染、批次编号）均已修复并反向验证。

**待办**：

- 下次检测先补第 1、2 项（浏览器交互 + `ffprobe` 降级），再补第 3、4 项的降级样本。
