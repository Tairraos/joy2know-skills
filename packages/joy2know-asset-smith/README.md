# 技能专家构建师 · 晓得乐（joy2know-asset-smith）

> 做资产不难，难的是**做完能上架**。

## 他解决什么问题

「有个想法想做成技能」这句话背后，卡点通常不在想法，而在这一路：

- 该做**技能**还是**专家**？单飞还是组团？—— 拍脑袋选完，做了一半发现形态错了；
- `SKILL.md` 那 9 个必填字段、`plugin.json` 那十几个键，**填错一个就是一次解析失败**；
- 好不容易打包了，上传报「**未找到 SKILL.md**」—— 其实是**上传入口选错了类型**；
- 过了审又卡在「所选类目与应用类目不符」，不知道该改包还是改类目；
- 想改一个版本，不知道**哪些地方要一起改**，改完发现内嵌它的那个专家包还是旧的；
- 最后一步做头像：规格是 512×512、≤500KB，**但不知道怎么画、画完怎么裁**。

他把这一路补上：**定形态 → 填字段 → 打包过门禁 → 上传送审 → 跟踪维护**，
外加**头像从提示词到裁切**的一条龙。

## 三条底线

1. **平台规则一律不猜。** 没有实证的一律标「未实证」，并指向官方文档或官方邮箱 —— 绝不编一条看起来很像的规则。
2. **不代替你做业务判断。** 叫什么名字、选哪个类目、要不要收费 —— 给判据和推荐，决定权在你。
3. **不碰你的凭证。** 需要登录时引导你自己完成，不索取、不保存账号信息。

## 头像：先说清两条路（这是他与众不同的地方）

做图标前他**一定会先问**：

> 这个头像你想**自己生成**，还是**让 WorkBuddy 画**？

| 你选 | 他给你 |
|---|---|
| **自己生成** | 一段**可直接粘贴**的生图提示词。性别 / 专业服装 / 专业道具按专家功能选好，风格骨架写死为「2.5D 头像，半身，头部较大的可爱造型，非写实，成年亚洲面孔」；**有参考图就按参考图脸型** |
| **让 WorkBuddy 画** | 一段**3/4 竖版**的提示词（**上下留白、中间方形画头像**）+ 一步裁切命令，产出干净的 512×512 |

**为什么要绕这一下**：WorkBuddy 生成的图**右下角带水印**。
画成 3/4 竖版、上下留白，水印就落在**下方空白区**；再**居中裁出中间方形**，
水印一起被切掉 —— 成品是干净方图。**这是为了躲水印的工程要求，不是审美偏好。**

裁切脚本自带反向自检：**故意造一张带水印的图，验证「裁完水印真的没了」**，
并额外验证「不清洗时水印确实还在」—— 免得这个检查变成橡皮章。

## 六个内置技能（各自也能单独用）

| 技能 | 管什么 |
|---|---|
| **资产字段规范** | 字段填什么：9 必填、`plugin.json` 全字段、三套分类、体积上限、zip 结构 |
| **技能包组装** | 形态怎么定：归置四选一、单飞判据、`description` 写法、系列一致性 |
| **资产包门禁** | 怎么证明做对了：四道门、假测试九形态、反向验证、检测报告怎么写 |
| **发布与驳回** | 传不上去怎么办：入口类型、三类驳回、**要不要抬版本号**、类目驳回找谁 |
| **资产状态追踪** | 现在什么状态：四态模型、「审核通过 ≠ 上架」、记账字段 |
| **资产包维护** | 改动波及哪里：内嵌联动、派生信息漂移、检测报告失真、头像三处同步 |

## 包内容

```
joy2know-asset-smith/
├── .codebuddy-plugin/plugin.json     核心配置
├── agents/joy2know-asset-smith.md    角色定义（系统提示词）
├── avatars/expert.png                头像 512×512（由构建注入）
├── scripts/crop-avatar.py            头像裁切：3/4 生成图 → 512×512
├── references/avatar-prompts.md      头像三要素映射表 + 两条路线提示词模板
├── skills/…                          六个内置技能（由构建注入）
└── README.md
```

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/joy2know-asset-smith.md`、`skills.json`、
> `scripts/crop-avatar.py`、`references/avatar-prompts.md` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-asset-smith.png` 注入；
> `skills/` 由构建按 `skills.json` 声明的名单复制**唯一真源**（六个技能仍可独立上架）。

## 怎么用

| 你说 | 他做 |
|---|---|
| 我有个想法，想做成 WorkBuddy 技能 | 先归置形态（四选一 + 两条抓手，**给结论和理由**）→ 再逐项填字段 → 打包 → 过门禁 |
| 帮我给这个专家设计头像 | **先问**你自己生成还是让 WorkBuddy 画 → 按路线给提示词 / 给裁切步骤 |
| 我的技能被驳回了 | 判是哪一类驳回（解析失败 / 类目不符 / 内容）→ 给出处置顺序与**是否抬版本号** |
| 我要更新一个已上架的技能 | 报出这是「更新版本」路径 → 提醒两道硬校验（包名一致、版本必须递增） |
| 这个报错什么意思 | 先给「你会看到什么 → 为什么 → 怎么办」，不追责 |
