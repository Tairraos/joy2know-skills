# 选题策划专家（joy2know-topic-planner）

> 把「下周发什么」从拍脑袋，变成按判据筛、按维度打分。

## 他解决什么问题

推广最难的一步不是写，是**决定写什么**：

- 一批想法摆在桌上，凭感觉挑一个，做完发现没人看；
- 追了个热点，数据很好，但没人记住你是谁；
- 想「多出几条总有一条中」，结果池子里一半是根本不该做的方向。

在**推广链的最上游**动手：先把原料过一道筛子，再把剩下的逐条打分。**分数不是重点，重点是同一个分数对不同人是一样的** —— 争「够不够爆」争不出结果，指分数可以。

## 三条底线

1. **筛在打之前。** 12 条心法里第七条是红线，红线命中一条，这个方向直接淘汰，不进入打分环节。
2. **⑥⑧ 是分界线。** ⑥卖点承载、⑧转化承接这两维，是推广选题与流量选题的唯一区别。只有 ①–⑤ 高分而 ⑥⑧ 低分的，会爆，但人留不下来 —— 脚本会对这个组合单独告警。
3. **分数由脚本算。** 阈值与告警硬编码在 `scripts/score.py` 里。觉得判定不对，改的是各维输入分，不是总分。

## 包内容

```
joy2know-topic-planner/
├── .codebuddy-plugin/plugin.json            核心配置
├── agents/joy2know-topic-planner.md         角色定义（系统提示词）
├── avatars/expert.png                       头像 512×512（由构建注入）
├── skills/joy2know-viral-topic/             内置技能（方法论与打分器，由构建注入）
│   ├── SKILL.md                             四张表 + 流程 + 输出模板
│   ├── references/
│   │   ├── method.md                        心法判定边界 · 8 维打分完整锚点
│   │   └── examples.md                      三条正反例：35 分 / 18 分 / 31 分带告警
│   └── scripts/
│       ├── score.py                         打分器（阈值与告警硬编码）
│       └── selftest.py                      判据自检（32 项，含文档锚点一致性）
└── README.md
```

**方法论主体在 `skills/joy2know-viral-topic/`，与独立上架的技能包同源。** 角色定义只规定流程与验收标准，不重复技能内容 —— 避免同一份规则两处维护导致版本漂移。

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/joy2know-topic-planner.md`、`skills.json` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-topic-planner.png` 注入；`skills/` 由构建按 `skills.json` 声明的名单，
> 从 `packages/<技能名>/` 复制**唯一真源**（本包内不存副本）。

## 怎么用

装上之后直接提问即可，不需要点名模式。

| 你说 | 他做 |
|---|---|
| 给我出一批能推广的选题 | 取原料 → 心法筛 → 基因匹配 → 打分 → Top 3 |
| 这几条选题帮我打个分 | 逐条跑打分器，出池 + 排名 + 淘汰区 |
| 这条内容很火但没带出货 | 查 ⑥⑧ 两维，说明它为什么是流量选题 |
| 我什么都还没想好 | 三问逼出原料，或先给一版标注了假设的占位原料 |
