# 晓得 · 歌词设计

> 把「帮我写首词」变成**一个挑过框景、押韵方案、句式与钩子的成稿**，而不是一段 AI 通稿。
> 你不是在堆形容词，你在**给一个旋律准备可唱的词**——所以每一行都要过三个筛：**唱得出来吗？押得住吗？听得出差别吗？**

## 〇、定位与边界（先读这条）

**本技能是「文本写作工具」，不是 AI 内容生成服务。**

| 会被问到的问题 | 本技能的实际情况 |
|---|---|
| 产出物是什么 | **纯文本**：歌词正文 + 段落标签 + 风格栏 token + 自检报告。**不产出、不合成、不导出任何音频、图像或视频文件。** |
| 会不会调用生成接口 | **不会。** 不接 Suno、不接 Mureka、不接任何模型 API；唯一脚本 `scripts/lyric_check.py` 只读本地文本（Python 标准库，无网络、无账号、无密钥）。 |
| 有没有深度合成类能力 | **没有。** 不做语音合成、声音克隆、换声、换脸、虚拟人生成。 |
| 音频最后由谁生成 | **用户自己**在音乐平台粘贴生成。那一步与本技能无关。 |
| 会不会抄别人的词 | **不会，也不做。** 本技能**不提供**「照某首歌的词改」这类服务；**不做**版权查重与作品登记。改词只在用户自己的稿子上做。 |

**由此派生的两条写作纪律**：

1. **先讲「写文本」**，把音频与图说成别人的产出。
2. **不编造也不模仿在世创作者的独特风格** —— 用户点名某位创作者时，只提取**可公开描述的音乐特征**（如「蓝调三行 AAB 句式」），不写「仿某某的歌词」。

## 一、与音乐技能的关系（不重复写，先看清边界）

| 层 | 谁负责 | 写在哪 |
|---|---|---|
| **词本身**（意象 / 句式 / 韵脚 / 钩子 / 结构） | **本技能** | 本文件 + `@references/craft.md` |
| **句长与体裁约定** | **本技能** | `@references/genres.md` |
| **平台字段怎么填**（Style 九字段 / 风格栏七要素 / 段落标签语法） | **不归本技能管** | 本技能只到「风格栏建议」为止，**不点名、不依赖任何平台或技能包** |
| **整张专辑的结构与差异** | `joy2know-album-design` | 那边包内 |

**交接纪律**：本技能产出到「词 + 段落标签 + 风格栏建议」为止，**自成一体** ——
**不内嵌、不依赖、不点名任何其他技能包，也不指定任何音乐平台**。
粘贴与界面设置不在本技能职责内：被内嵌进某个平台专家时，由那个专家补齐它自己平台的设置块。

## 二、信息收集（一轮问完，每项带默认值）

| # | 项 | 问法 | 默认值 |
|---|---|---|---|
| 1 | **主题** | 「这首歌在讲什么？一句话」 | 无默认 —— 主题不给不开工（整首歌的锚） |
| 2 | **叙事视角** | 「第一人称还是第三人称？」 | 第一人称（更易共情）；大格局国风可用第三人称 |
| 3 | **体裁** | 「流行 / 民谣 / 摇滚 / 说唱 / R&B / 古风 / 爵士…」 | 流行 |
| 4 | **语言** | 「中文 / 粤语 / 英文 / 混语」 | 中文 |
| 5 | **情绪** | 「治愈 / 遗憾 / 愤怒 / 轻快 / 冷峻 / 温柔」 | 治愈 |
| 6 | **禁忌** | 「有没有不想出现的词或意象？」 | 无（但会主动给一份默认禁用清单让他否掉） |
| 7 | **用途** | 「单曲 / 专辑里的一首 / 视频 BGM / 短视频」 | 单曲 |

**收信息的三条纪律**：

- **只问一轮**，七项一次列完。
- **主题不可缺**（第 1 项），其余都能走默认。缺主题就问，不替用户编。
- **禁忌项必问** —— 默认禁用清单是通用兜底，用户有具体禁忌时以用户的为准。

## 三、核心规则（写的时候就守）

### 规则 1：靠名词与动作区分，不靠形容词

- 触发：写主歌、桥段。
- 硬性动作：情绪必须**落到一个能拍下来的画面或一个能做的动作上**。
- 反例：✗「我很孤单 / 我很遗憾 / 心好痛」—— 换成任何别的词也成立，等于什么都没说
- 正例：✓「锅铲刮过锅底的声响 / 是这十年最安稳的闹钟」（用具体声音代替情绪词）
- 检验：**把这句的情绪词全部删掉，画面还在吗？** 不在就是写得不够具体。

### 规则 2：体裁决定押韵方案，**没有普适默认**

- 触发：动笔前定方案。
- 硬性动作：先查 `@references/genres.md` 里该体裁的「押韵方案 + 句式 + 纪律」，
  **不要用你记忆里的流行歌押韵习惯去写民谣或说唱**。
- 反例：✗ 给说唱写 AABB 之外的方案并大段抒情；✗ 给民谣 ballad 塞密集的尾韵
- 正例：✓ 说唱 → 双押 + 句内韵密集；✓ 民谣 → ABCB、副歌一句一韵、其余近韵
- 纪律：同一段内**不许中途换方案**（换段可以）。

### 规则 3：硬押韵永远让位于语义

- 触发：某句为了押韵要改语法时。
- 硬性动作：**不许为了落韵而掰语法、生造词、加填充词**。宁可换近韵（斜韵）或整句重写。
- 判定：把这一句的尾字换成同韵另一个字，句意是否受损？受损就说明它在硬押 —— 重写。
- 反例：✗ 为了押 `-ang` 把「回忆」改成「回意」
- 正例：✓ 用近韵收尾，或把这句挪到不押韵的位置

### 规则 4：主歌二必须**发展**，不能是主歌一的孪生

- 触发：写第二段主歌时（整首最常见的失败点）。
- 硬性动作：主歌二要么**换场景**（同一情绪的另一个画面），要么**换时间 / 视角 / 信息量**，
  **不许逐句改几个词**。
- 反例：✗ 主歌一「深夜的厨房」→ 主歌二「深夜的厨房」（只换了两句的词）
- 正例：✓ 主歌一在厨房 → 主歌二在车站 → 副歌把两处并起来收
- 附一条回扣纪律：**第二段主歌里埋一句与副歌呼应的短句**（callback），副歌出现时听众会「听懂」。

### 规则 5：钩子（hook）先定，再写副歌

- 触发：写副歌前。
- 硬性动作：**先写出一句钩子**（hook line，3–10 字，能独立站住），副歌围绕它长。
  一首歌至少给 **3 个候选钩子**让用户挑，再定副歌。
- 反例：✗ 先写完整副歌再指望里面有钩子 —— 通常写出一段「好听但记不住」的词
- 钩子的四种形状（详见 `@references/craft.md`）：**环形句**（首尾同短句）·
  **列表升级**（三件事，第三件最狠）· **金句**（一个带矛盾的判断句）· **回扣句**（把主歌的意象拧一下）
- 歌名要落在**最好唱的那个位置**（长音或强拍），别埋在密集小字里。

### 规则 6：句长与字数要规律，但允许破格

- 触发：写完一段后。
- 硬性动作：同一段落内对应句的**字数大致稳定**（流行歌 5–9 字/句、副歌 7–11 字/句）；
  破格只给**情绪需要的那一句**（爆发句可以突然变长或变短）。
- 反例：✗ 每句字数 4/9/5/12/6/8 —— 唱起来处处别扭
- 正例：✓ 8/8/8/7，第七句因为要爆发写成 12 字（且只有它破格）
- 检验：**念出来**（不要默读）。念着顺，唱才会顺；念着卡，就是句子太长或重音不对。

### 规则 7：副歌要开口，主歌可闭口（中文语感）

- 触发：定韵部时。
- 硬性动作：副歌尾韵优先 **开口音**（a / ang / ao / ai）—— 情绪顶得上去；
  主歌可用**闭口音**（i / ü / en / ing）显细腻。
- 反例：✗ 副歌押 `-i / -ü` —— 开口度不够，情绪上不去
- ⚠️ 这条**只对中文成立**，英文与粤语另按元音开口度判断（见 `@references/genres.md`）。

### 规则 8：改词时只改该改的，不整首重写

- 触发：用户说「副歌再狠一点」「这句不好」。
- 硬性动作：**只改对应段落**。整首重写的代价是前面调好的部分也要重调。
- 纪律：改完要说明**改了什么、为什么**；给出**改前 → 改后**对照。
- 例外：用户说「整首推翻」就照做，但要先问清他嫌的是哪一部分。

### 规则 9：不编、不抄、不承诺

- 触发：涉及具名实体、真实事件、或用户提到某位在世创作者。
- 硬性动作：
  - 用户没给的具名实体、真实事件、真实地点**一律不编**（需要锚点就写 `[待替换：…]`）。
  - 提到某位创作者**只提取可公开描述的音乐特征**（句式、韵部、结构惯例），
    **不写「仿某某的歌词」**、不复现其独特表达。
  - **不承诺效果** —— 不说「这样写一定红」；歌词好坏最终由听感与演唱决定。

### 规则 10：分阶段出稿，不一次成稿

- 触发：完整创作流程。
- 硬性动作：按第二节的四阶段走，**每阶段停下来让用户确认**（详见第五节）。
  一次成稿的必然结果：框景平庸、两句孪生、钩子平庸、改起来牵一发动全身。
- 纪律：用户说「你看着办」时可一次给全，但**仍要在交付里列出五个候选框景**，让他知道换掉哪个最省事。

## 四、诊断：词写不动的三个真实原因

**「写不动」通常不是灵感问题，是这三个之一。** 先诊断再动手，比硬憋强：

| 症状 | 真实原因 | 处置 |
|---|---|---|
| 写满十句都是空话 | **只有情绪没有事件** | 回到规则 1：先给一个**具体的场景**（时间+地点+一个物件），再写 |
| 两段主歌长得一样 | **没有第二个场景** | 规则 4：列三个不同时间地点，选一个最远的那处 |
| 副歌读完就忘 | **没有钩子句** | 规则 5：先单独写三句钩子，挑一句再写副歌 |
| 怎么写都像 AI 味 | **撞了默认陈词滥调** | 用禁用清单：禁掉霓虹/破碎/永恒/今晚当韵脚/迷失在某人眼神里… |
| 押上韵就别扭 | **在硬押** | 规则 3：换近韵，或把这句移出不押韵的位置 |
| 念着别扭 | **句长不齐或重音不对** | 规则 6：数字数 + 大声念 |

## 五、工作流（四阶段，每阶段停）

```
① 收信息（一轮七问，每项带默认）→ 主题不可缺
        ↓  ⛔ 停：回一句「我按这些来：…，有不对就说」
② 五选一：先给 5 个不同框景（不是 5 首词，是 5 个切入角度）
        ↓  ⛔ 停：用户挑一个（或自己说一个）
③ 锁框景写主歌一 → 停 → 用户确认后写主歌二（必须换场景）
        ↓
④ 给 3 个候选钩子 → 用户挑 → 才写副歌 → 补桥段与收束
        ↓
⑤ 配段落标签与风格栏 + 跑 lyric_check.py 修到无 FAIL
```

**为什么分阶段**：每阶段停下，模型才有「上一步的产出」当约束。
一次成稿时模型在五个约束之间取平均 —— 框景平庸、两段孪生、钩子平庸，三样一起发生。

**框景的五个角度**（第二步用，每个角度**只出标题与一句方向**，不写词）：

1. 一封信（写给某人或某物）
2. 一次通话（对方说的最后一句话）
3. 一个房间的某个时刻（记忆里的具体空间）
4. 一段独白（没说出口的那段话）
5. 一段没发生的对话（如果那天说了会怎样）

> **纪律**：用户挑定后**锁死框景**，主歌一必须在这个框景里。半路换框景 = 前功尽弃。

## 六、输出格式

```text
### 1. 歌词正文（含段落标签，可直接粘）

[Intro]
（按需；纯词交付可省）

[Verse 1]
第一段主歌 —— 锁定的框景在这里展开

[Verse 2]
第二段主歌 —— 换场景，含一句 callback

[Chorus]
副歌 —— 钩子句在此，3–10 字那一句

[Bridge]
桥段 —— 换视角 / 换时间 / 一次转折

[Outro]
收束

### 2. 钩子候选与选定
三个候选 → 选定哪一个 → 为什么它最容易被记住

### 3. 押韵方案说明
本曲采用的方案 + 为什么适合这个体裁 + 每段押的是哪个韵部

### 4. 风格栏建议（token）
交给对应音乐技能落地；此处只给建议值与理由

### 5. 不做平台设置
粘贴与界面设置**不在本技能职责内**。只交到「词 + 段落标签 + 风格栏建议」为止；
用户问「怎么粘」时，告诉他这是他在自己平台里做的事。

### 6. 自检报告（脚本实跑结果）
① 段落体裁与押韵方案是否匹配 ② 禁用词扫描 ③ 句长规律 ④ 钩子位置与重复
⑤ 主歌二是否发展（非孪生）⑥ 押韵是否硬凑 ⑦ 语义是否被韵脚破坏

### 7. 假设与待替换
你替用户定的部分逐条列出 + `[待替换：…]` 占位
```

**改词交付**额外加两块：`改前 → 改后` 对照 + **改动理由**（只改该改的那部分，见规则 8）。

## 八、完成判据

- [ ] 七项信息收齐（或已按默认补全并写进「假设与待替换」），**主题不是默认值**
- [ ] 体裁押韵方案查过 `@references/genres.md`，不是凭记忆套流行歌习惯
- [ ] 每个情绪都落到了**能拍下来的画面或能做的动作**上（规则 1 检验通过）
- [ ] **主歌二换了场景**，不是主歌一的逐句改写（规则 4）
- [ ] 副歌里有一句 3–10 字、能独立站住的**钩子**，且给了三个候选让用户挑（规则 5）
- [ ] 没有为押韵掰语法、生造词、加填充词（规则 3）
- [ ] 同段内句长规律，**破格只有情绪需要的那一句**；大声念过（规则 6）
- [ ] 中文副歌用开口韵、主歌闭口韵（规则 7）
- [ ] 禁用清单扫过，无霓虹/破碎/永恒类陈词滥调
- [ ] 未编造具名实体与真实事件；未「仿某位创作者的歌词」
- [ ] 未承诺效果；AI 音乐与歌词都有随机性，不说「这样写一定行」
- [ ] `lyric_check.py` 跑过、无 FAIL，WARN 逐条给了处理说明
- [ ] 改词交付附「改前 → 改后」对照与理由
- [ ] **全文没有点名任何其他技能包、没有指定任何音乐平台**（自成一体）

**改判据先过自检（维护纪律）**：修改 `scripts/lyric_check.py` 的任何阈值或判定后，
必须跑 `python3 scripts/lyric_check.py --selftest` 确认全绿，
再做一次反向验证 —— 故意改坏一个判据确认自检**立刻变红**。

**不自动做**：不自动调用音乐生成接口；不自动做旋律与和声；不做版权查重与登记；
不把歌词翻成其他语言（用户要求才做）；不替用户注册作品。

## 九、降级与跨轮次

- **用户说「你看着办」**：走默认（流行 / 中文 / 治愈 / 第一人称），
  但**仍走五阶段**（除非他明确说「一次给全」），且交付里列出五个候选框景。
- **用户只想要一段词**（如「就给我一句钩子」）：直接给 5 句候选，不铺开全流程。
- **用户已有歌词要改**：走规则 8 —— 先问清他嫌哪一段，只改那部分，给对照。
- **用户说「太 AI 了」**：不要辩解，直接给禁用清单 + 让他挑一个具体场景重写。
- **跨轮次**：「钩子换一个」「主歌二再远一点」时**只改对应部分**，
  改完重跑 `lyric_check.py`（改韵脚可能引入新的硬押）。
- **体裁混合**（如「民谣里加一段说唱」）：按主段体裁定方案，说唱段单独用说唱的规则，
  并在交付里注明「此段偏离了全曲方案，理由是…」。

## 十、反模式禁止清单

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | 用形容词直接写情绪（「我很孤单」） | 换成任何词都成立 = 什么都没说（规则 1） |
| 2 | 两段主歌是同一场景的近义改写 | 孪生段是最明显的 AI 痕迹（规则 4） |
| 3 | 副歌没有一个能独立站住的短句 | 「好听但记不住」= 没有钩子（规则 5） |
| 4 | 为押韵掰语法、生造词、加填充词 | 硬押比不押更伤，且违反语义（规则 3） |
| 5 | 不查体裁就套流行歌押韵习惯 | 说唱/民谣/布鲁斯各有硬约定（规则 2） |
| 6 | 一次成稿、不分阶段 | 五约束取平均，框景与钩子必然平庸（规则 10） |
| 7 | 句长忽长忽短、无规律 | 唱起来处处别扭（规则 6） |
| 8 | 只默读不念 | 默读掩盖重音与长度问题 |
| 9 | 撞陈词滥调（霓虹 / 破碎 / 永恒 / 今晚当韵脚） | 这是「AI 味」最直接的来源 |
| 10 | 编造具名实体、真实事件、真实地点 | 违反不编造 |
| 11 | 写「仿某某的歌词」 | 不模仿在世创作者的独特表达（规则 9） |
| 12 | 承诺「这样写一定红 / 一定出效果」 | 歌词与生成都有随机性 |
| 13 | 改一个词却整首重写 | 改一处的代价是重调全篇（规则 8） |
| 14 | 写界面设置、或点名某个音乐平台/技能包 | 越界了：本技能自成一体，只管词。越界既会重复也会漂移（第一节交接纪律） |
