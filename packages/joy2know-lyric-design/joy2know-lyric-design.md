## 四、门 3 · 合理性结论

- **规则是否自洽**：✅ 无互相打架。规则 1（名词）与规则 6（句长）互补不冲突；
  规则 2（体裁方案）与 `genres.md` 表一致；规则 7 明确限定「只对中文成立」，不越界到粤语/英文。
- **★ 消掉的一处自相矛盾**：初版脚本把「副歌无 3–10 字段」直接判为无钩子，
  但自检样本里「其实我不止这些」（7 字）被判成了钩子 —— **判据把连接词句也抓进来了**。
  已改为 3–9 字 + `HOOK_STOPWORDS` 双重条件，并在提示里点名「塞满连接的句子不算钩子」。
- **推断是否标推断**：✅ 韵母判定用内置近似表，脚本头 `PINGYIN_NOTE` 明确写「这是近似，
  多音字/生僻字会失准，故 W 类一律降为 WARN 不判红」。
- **错误提示是否指导下一步**：✅ 每条 WARN 带 `↳` 修复提示，指向 references 的具体章节
  （如「钩子四型见 references/craft.md 第四节」）。
- **边界是否优雅**：✅ 无标签 → L0 FAIL 而非静默通过；单行段落 → 记 OK「押韵不适用」；
  韵母识别不足 → 点名未识别尾字。
- **零依赖是否守住**：✅ 只import 标准库；韵母表是本包自带的**数据**（不是依赖）。
- **值来源可追溯**：✅ 体裁押韵方案来自调研（bitwize 的体裁对照表 + 中文技法文章），
  在 `genres.md` 第一节注明；十三辙是传统韵部划分，属公开常识。

2. **钩子判据过宽**：3–10 字把「其实我不止这些」也抓成钩子。已收紧为 3–9 字 + 连接词黑名单。

   已改为点名未识别尾字 + 说明「只查了部分行」，并区分 OK 级（覆盖 ≥75%）与 WARN 级（更低）。

## 六、未覆盖项 / 已知缺陷 / 待办

**未覆盖项**（下次检测优先消掉）：

1. **歌词的文学质量未验证**：本报告验结构与判据，**不验词好不好**。
   画面是否成立（规则 1）、主歌二是否真发展（规则 4）、语义是否被韵脚破坏（规则 3）
   这三条**必须人读**，脚本在文件头已显式声明「假装能查语义比不查更危险」。
   需至少找 3–5 首真实成品词做人工评审对照。
2. **粤语 / 英文歌词未覆盖**：L6 开口韵判据只对普通话成立（十三辙是普通话韵部）；
   英文与粤语的押韵方案在 `genres.md` 里写了，但**没有脚本判据**。
3. **多音字与生僻字的韵母误判未量化**：内置韵母表按常见读音取一个，
   「长(cháng/zhǎng)」「行(xíng/háng)」这类会判错。**未量化误判率**。
4. **平台侧真实上传未做**：本包从未提交（①），入口与类目建议均未实证。
5. **与两个音乐专家的实际协同未跑**：只做了职责边界的文档声明，
   **没有真跑一次「在专家里说『帮我打磨这首歌的词』」的完整链路**。

**已知弱项**（不阻断上架，记在案）：

- **W1 · 三条核心规则不可机检**（规则 1/4/9）：语义与审美判断，脚本不碰。这是**有意的设计取舍**，
  已在脚本头与门 2 表三处声明 —— 但也意味着「六条门禁全过」**不等于「词写得好」**。
- **W2 · 韵母表覆盖率有限**：目前收录约 300 字，覆盖常见尾字；生僻字会落到 WARN。
  需要时可用 `references/genres.md` 第六节的人工十三辙判断兜底。
- **W3 · `description_zh` 83 字**：平台不查中文长度；信息量由 `description`（388 字）承担，无实际风险。

**待办**：

- 提交平台（走**技能入口**；类目建议「内容创作 > 文案」，
  ⚠️ 若被机器判「深度合成 > AI创作」：**先找客服人工复审，别改包**）。
- 画图标（**当前是占位图，等小乐亲手画**；技能图标不进 zip，后台发布时单独上传）。
- 找 3–5 首真实成品词做人工评审，评估未覆盖项 1。

| SkillHub「故事成歌」 | 多阶段 + 用户手动切模型推进 | 强依赖用户每阶段手动切模型，体验断裂；且**最后要调 Suno 生成 WAV** —— 本包只产文本 |
| `suno-cn-music` 类技能 | 直接调音乐生成接口出 MP3 | **违反铁律 11**：产出会被判「AI 生成服务」，且我们要的是「只产提示词文本」 |
| a5c「lyric-writing」 | 歌词里嵌 `[belt] / [falsetto] / [building]` 等演唱提示 | 那是**给生成器的指令**，不是歌词本身好坏；本包把它归到「风格栏建议」而非歌词正文 |
| 各类「押韵检测 MCP」（mandarin_rhyme 等） | 调外部 MCP 服务查韵脚 | **要联网凭证** → 违反「不带账号与密钥」；本包改为内置近似表 + 明确标注覆盖率 |

### 一句话结论

**市场上没有一类技能覆盖「中文歌词的体裁押韵约定 + 陈词滥调清理 + 可机检纪律」**——
英文那套（bitwize）押韵表做得好但不懂中文声调字数；
中文那套零散在文章里没有成体系；
做结构注释的那类产的是给生成器的指令不是词本身。
**这就是本包的位置。**
