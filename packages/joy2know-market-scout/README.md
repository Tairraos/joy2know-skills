# 竞品与受众情报专家（joy2know-market-scout）

> 先把外面看清楚，再决定里面怎么讲。

## 他解决什么问题

绝大多数推广方案死在一个地方：**定位是拍脑袋定的，而且事后无法验证对错。**

- 说要服务「注重健康的年轻人」，但这个人在现实里找不到；
- 知道同类在发内容，但说不清哪条真跑出来了；
- 感觉「这个角度没人做过」，其实只是自己没看到。

把这件事变成可复核的：**每条观察都指得回一条带时间的内容，每个推断都标出来，查不到的数据就写「未获取到公开数据」。**

## 三条底线

1. **能指回具体内容。** 结论统一写成「对象 + 内容/动作 + 表现 + 时间」。写不出这个格式的，是感觉，不是情报。
2. **事实与推断分开。** 推断一律标 `【推断】` 并给依据 —— 拿结论做决策的人必须知道哪条是铁证、哪条是猜的。
3. **不编数据。** 查不到就写「未获取到公开数据」，改用可观察的替代信号（更新频率、形式变化、评论区提问方向、有没有投流迹象）。**一个假数字会污染后面所有环节，而它看起来和真的一样。**

## 包内容

```
joy2know-market-scout/
├── .codebuddy-plugin/plugin.json          核心配置
├── agents/joy2know-market-scout.md        角色定义（系统提示词）
├── avatars/expert.png                     头像 512×512（由构建注入）
├── skills.json                            内嵌技能清单（本包不内嵌技能）
└── README.md
```

**本包不内嵌技能** —— 它的方法论是「观察格式 + 事实与推断的纪律」，属于角色定义的一部分，没有可复用的独立计算逻辑，硬拆成技能反而是负担。

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/joy2know-market-scout.md`、`skills.json` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-market-scout.png` 注入。

## 怎么用

| 你说 | 他做 |
|---|---|
| 帮我看看这个品类别人是怎么推的 | 列候选竞品 → 你确认 → 逐个扒内容 → 归纳套路 → 找空位 |
| 我的目标人群到底是谁 | 受众卡（具体到能想象出一个人）+ 聚集地 |
| 还有哪个角度没人认真占过 | 空位判断表 + 一句话结论 |
| 我自己想不出竞品 | 按品类给候选名单，你确认或划掉之后再开查 |
