# 天音音乐大师（joy2know-tianyin-maestro）

> 把「一段想法」写成能直接粘进网易天音「AI作歌」的输入。

## 他解决什么问题

网易天音的「AI作歌」有两种模式、两套输入结构，写错位置就等于白跑一次：

- 简易模式只有一个「创作灵感」框——把歌词写进去，平台会把它当风格词处理；
- 高级模式是「风格描述 + 歌词」双栏 + 一组控件（人声性别 / 18 个风格标签 / 18 位虚拟歌手 / 副歌前置 / 歌名）——
  文本里写「温柔女声」、控件选男声，三处互相覆盖，出来的不是你要的；
- 「纯音乐」开关只在简易模式有，高级模式找不到它——器乐意图要写进风格描述、歌词栏留空；
- 中文歌词不标段落与重复位置，咬字糊、结构跑。

他站在**粘贴之前**动手：把想法写成对应模式的输入文本（灵感四要素一段话，或风格描述 + 歌词两栏），
按 18 标签 × 18 歌手的适配关系配好控件，跑一遍结构校验，再附上粘贴前要点对的界面设置。

## 三条底线

1. **只产出输入文本。** 不生成音频、不调用任何生成接口、不带账号与密钥；粘贴生成是用户自己
   在网易天音里的动作。AI 音乐有随机性——他提高命中率，不承诺效果。
2. **控件设置块不许省。** 模式、人声性别、虚拟歌手、副歌前置、歌名、纯音乐开关、参考音频要求——
   它和主输入文本一样是交付物的一部分，缺一块就是让用户在错误的地方花时间。
3. **结构校验由脚本算。** 校验器在 `skills/joy2know-tianyin-musician/scripts/`，
   FAIL 修到零才交付，WARN 逐条给处理说明；觉得判定不对，先回技能规则核对，不临场发明第三种口径。

## 三条路径

| 你说 | 他走 | 交付 |
|---|---|---|
| 给我写一首能粘进网易天音的歌 | 单曲路径（`joy2know-tianyin-musician`） | 灵感或两栏文本 + 控件设置块 + 假设与待替换 |
| 帮我写首歌词 / 换个钩子 | 作词路径（`joy2know-lyric-design`） | 歌词正文 + 段落标签 + 界面设置 + 自检报告 |
| 设计一张专辑 / 专辑曲目表 | 专辑路径（`joy2know-album-design`） | 专辑规划文档 + 逐首粘贴清单（两份 md） |

**歌词正文的写法一律以作词技能为准**（本专家不另立一套歌词规则）；**界面设置块永远以单曲技能为准**
（作词技能不重复定义界面规则）。三条路径可以串起来：先设计专辑 → 再给某首写词 → 最后拼成可粘贴的输入包，
但每一段各自用自己那条路径的技能。

不重复技能内容——避免同一份规则两处维护导致版本漂移。

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/joy2know-tianyin-maestro.md`、`skills.json` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-tianyin-maestro.png` 注入；`skills/` 由构建按 `skills.json`
> 声明的名单，从 `packages/<技能名>/` 复制**唯一真源**（本包内不存副本）。

## 怎么用

装上之后直接提问即可，不需要点名模式。

| 你说 | 他做 |
|---|---|
| 给我写一首能粘进网易天音的歌 | 五问走默认值 → 对应模式的输入包 + 控件设置块 |
| 写一首深夜厨房主题的抒情流行 | 四要素叙事句 → 配祝宁或林小甜 → 脚本校验 → 交付 |
| 这两段文本帮我检查一下再粘 | 跑结构校验器，FAIL 修零、WARN 逐条说明 |
| 我什么都还没想好 | 全默认（民谣底、女声、默认音色）直接产出，替你定的项逐条写在「假设与待替换」 |
| 帮我写首歌词 / 换个钩子 | 走作词路径：七问 → 按体裁押韵 → 钩子候选 → 分阶段出稿 |
| 设计一张六首的专辑 | 走专辑路径：九问 → 两份 md（规划 + 粘贴清单） |
