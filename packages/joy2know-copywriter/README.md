# 推广文案编导（joy2know-copywriter）

> 交付的不是「文案方向」，是能直接复制粘贴、能照着念的成品。

## 他解决什么问题

写文案这件事，最费时间的从来不是「想不到」，而是**改到能发**：

- 拿到的是提纲和结构说明，还要自己填；
- 同一篇内容要发三个平台，复制粘贴过去就没人看；
- 标题堆了三个情绪词，读者一眼判定是标题党；
- 一眼看出是 AI 写的 —— 套话太多，转化率直接掉。

把「写」和「改到能发」之间的那一段全包了：**完整成品 + 按平台改写 + A/B 变体 + 两道门禁**。

## 三条底线

1. **成品必须能直接发。** 不给提纲、不给「这里可以补个案例」。缺关键信息时用 `【待补：……】` 显式标出，**不编一个填空进去**。
2. **平台不是转发，是改写。** 每个平台单独一版 —— 开头钩子、段落长度、字幕需求、结尾动作都不一样。
3. **两道门禁，不过不算定稿。** 合规词表（绝对化 / 承诺 / 诱导分享 / 肖像 / 品牌）与腔调门禁（`joy2know-humanize` 的脚本，退出码 0）都要过。

## 包内容

```
joy2know-copywriter/
├── .codebuddy-plugin/plugin.json          核心配置
├── agents/joy2know-copywriter.md          角色定义（系统提示词）
├── avatars/expert.png                     头像 512×512（由构建注入）
├── skills/joy2know-humanize/              内置技能（腔调门禁，由构建注入）
│   ├── SKILL.md
│   ├── references/                        规则表 · 基线 · 不可改清单
│   └── scripts/                           scan.py / fix.py / guard.py
└── README.md
```

**腔调判定的方法论在 `skills/joy2know-humanize/`，与独立上架的技能包同源。** 角色定义只规定「什么时候必须跑门禁」，不重复规则内容。

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/joy2know-copywriter.md`、`skills.json` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-copywriter.png` 注入；`skills/` 由构建按 `skills.json` 声明的名单复制**唯一真源**。

## 怎么用

| 你说 | 他做 |
|---|---|
| 把这条选题写成能直接发的成品 | 定形态 → 写初稿 → 平台适配 → 过两道门禁 → 出变体 |
| 这篇改成小红书版 | 按平台脾气重写（不是缩短） |
| 帮我写个 30 秒口播稿 | 写成能直接念的连续文本，不留结构标记 |
| 这段一眼看出是 AI 写的 | 跑腔调扫描 → 只改命中处 → 过门禁 |
| 给我两个不同方向的版本 | 主版本 + 变体 B，并说明各自赌什么 |
