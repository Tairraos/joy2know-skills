# 晓得 · 专辑设计

> 把「我要做一张专辑」变成**一份能照着做的专辑规划文档 + 一份能照着粘的逐首清单 + 一个改一处就全篇重算的生成脚本**。
> 你不是在写歌，你是在**做专辑企划**：先定音色口径与结构差异，再把每首落成可粘贴的提示词文本。

## 〇、定位与边界（先读这条）

**本技能是「文本写作工具」，不是 AI 内容生成服务。**

| 会被问到的问题 | 本技能的实际情况 |
|---|---|
| 产出物是什么 | **纯文本**：专辑规划 Markdown、逐首粘贴清单 Markdown、一个生成脚本。**不产出、不合成、不导出任何音频、图像或视频文件。** |
| 会不会调用生成接口 | **不会。** 不接 Suno、不接 Mureka、不接任何模型 API；两个脚本（`scripts/album_check.py`、`scripts/build_album.py`）只用 Python 标准库，无网络、无账号、无密钥、无额度。 |
| 有没有深度合成类能力 | **没有。** 不做语音合成、声音克隆、换声、换脸、虚拟人生成，也不做音视频的生成或篡改。 |
| 音频与封面最后由谁做 | **用户自己**在音乐平台粘贴生成、自己在绘图工具出图。那两步与本技能无关，受那些平台的条款与用户账号约束。 |
| 在链条里的位置 | 只负责**把专辑意图写成结构化的文本描述与一套可执行的规划文档**，再做一次结构自检——交出去的是给人「粘贴」用的文本，不是可播放的成品。 |

**由此派生的两条写作纪律**（本文件与一切对外说明都遵守）：

1. **先讲「写文本」，把音频与图说成别人的产出** —— 不说「帮你生成一张专辑」，只说「帮你写好你要粘贴的那些文本」。
2. **不提第三方平台的账号档位、订阅、额度与计费** —— 平台控件的**操作方法**只在 `@references/platform-notes.md` 里按需讲。

## 一、先分清（这三层混在一起，专辑必塌）

| 层 | 是什么 | 落在哪 | 作用 |
|---|---|---|---|
| **专辑层** | 音色锚点、结构分配、差异矩阵、拍号调式口径 | 主文档第 1–7 章 | 保证 N 首是一张专辑，不是 N 首歌的拼盘 |
| **单曲层** | 每首的风格栏 token、歌词栏标签、意象与结构 | 主文档第 8 章 + 粘贴清单 | 保证每首能直接粘 |
| **文本层** | 生成脚本里的结构化数据（`tracks[]`） | `build_album.py` 的 `ALBUM` 字典 | **唯一真源**，两份 md 都由它渲染 |

**最常见的失败**：专辑层没做，直接写 N 个独立提示词 —— 结果每首都能生成，但放在一起像同一台机器出的货。
**第二常见**：主文档与粘贴清单各写一遍，改了曲目表忘了改清单 —— 于是清单和文档对不上，用户粘到的是旧版。

## 二、什么时候用这个技能（路由）

| 情形 | 判定信号 | 走哪条 |
|---|---|---|
| **A. 整张专辑** | 「做一张专辑」「规划专辑」「N 集」「EP」「tracklist」 | **本技能主路径**：信息收集 → 差异矩阵 → 三份产物 |
| **B. 单曲** | 「写首歌」「一首」 | **不适用本技能** —— 交给同包的单曲技能（`joy2know-musician` / `joy2know-mureka-musician`） |
| **C. 已有专辑，只要重排** | 用户已有曲目清单，要结构与差异 | 走A 的第 4–7 章（结构 / 曲目表 / 差异矩阵 / 拍号调式），第 8 章按已有曲目回填 |
| **D. 只要歌名候选** | 「先给我几个歌名」 | 走第三节的「曲名未定」分支，只出候选清单，不出全篇 |
| **E. 纯音乐专辑 / 游戏 OST** | 用途是 OST、BGM、音效包 | 走 A + 规则 3 纯音乐路径（**不开「纯音乐」开关**，靠歌词栏方括号编曲标签控流向） |
| **F. 平台不是 Suno / Mureka** | 用户要去别的平台 | 仍走 A，但第 2 章与第 8 章按目标平台字段改写，并**明确告知**本技能的字段口径是按这两个平台实测整理的 |

**与单曲技能的关系（不重复、只引用）**：本技能**不重写**单曲提示词的写法（语言声明、段落标签、方言锁、界面设置块），
那些一律以单曲技能为准；本技能只加专辑层，并在第 8 章**逐首引用**单曲技能的产出格式。
**同一份规则只写一遍** —— 专辑层与单曲层各自负责一件事。

## 三、信息收集（一次问完，每项都给默认值）

**这是本技能的第一步，也是最容易做砸的一步。** 收集不全就开工 → 后面全靠编；连环追问 → 用户烦。

### 3.1 必问九项（一轮列清单，用户能一次答完）

| # | 项 | 问法 | 默认值（用户不答就用） |
|---|---|---|---|
| 1 | **专辑名** | 「这张专辑叫什么？不确定我先给候选」 | 先出候选（见 3.3） |
| 2 | **用途** | 「游戏 OST / 个人发行 / 影视配乐 / 播客片头 / 其他」 | 个人发行 |
| 3 | **集数 N** | 「一共几首？」 | 6（3–12 之间最稳；超过 12 差异矩阵会很难撑住） |
| 4 | **主题** | 「这张专辑整体在讲什么？一句话」 | 从第 5 项的歌词主题里提炼 |
| 5 | **歌词主题** | 「每首歌分别写什么？给 N 个点子或一段话都行」 | 由主题拆成 N 个不重叠的生活切片 |
| 6 | **歌词风格** | 「歌词什么调性？治愈 / 冷峻 / 叙事 / 口语 / 古风 / 不写词」 | 治愈、有画面感、带人生哲理（与本系列单曲技能同底色） |
| 7 | **风格锚点** | 「有想靠近的作曲家或作品吗？」 | 不给锚点，但必须给一个**听感一句话**（见 3.2） |
| 8 | **听感** | 「一句话说清整体听感」 | 「安静、留白多、不煽情」 |
| 9 | **曲目名** | 「曲名定了吗？」 | 未定 → 先出候选清单（见 3.3） |

### 3.2 锚点缺失时的替代（不许跳过「风格锚点」这一格）

用户给不出作曲家 / 作品时，**不许把这一格空着** —— 空着会导致音色口径（第三章）写不出东西。
按顺序做替代：

1. **从听感反推**：用户说「安静、留白多」→ 锚点写成「极简编制、留白优先、低动态」这类**可落到 token 的描述**。
2. **从用途反推**：游戏 OST → 锚点写成「功能性配乐，服从场景，允许 loop」；影视配乐 → 「叙事主导，主题复现」。
3. **直接给三个候选锚点**让用户选（各附一句它会产出什么听感）。

**无论走哪条替代，最终都必须落成一句可执行的话**（例：「风格锚点是 Ólafur Arnalds 式的极简钢琴 + 弦乐垫」）。

### 3.3 曲名未定的两段式（不许直接编 N 个歌名就跑）

用户没定曲名时，**先只出候选清单，不出全篇**：

1. 给 **3 组 × 每组 5 个**中文曲名候选，每组对应一种命名策略：
   - **A 组·意象直取**：从歌词主题里的具体物象命名（例：灯塔 / 潮汐 / 六楼路灯）
   - **B 组·时间地点**：用时间或地点命名（例：凌晨四点半的洗衣房）
   - **C 组·动作或短句**：用一个动作或半句话命名（例：把伞留在门口）
2. 每个候选后**一句话注明意象来源**（来自第 5 项的哪个主题）。
3. 让用户**回复编号**（如「A2 B4 C1」）或自定。
4. 拿到选择后才生成三份产物，并按选择**重排全篇**（序章 / 收尾的位置要跟着名字的意象走）。

### 3.4 收集纪律（写的时候就要守）

- **只问一轮**，九项一次列完，用户能答几条答几条。
- **每项都带默认值** —— 默认值不是为了省事，是为了用户不答时也能开工。
- **不许连环追问**；问满两轮仍缺关键项（1 / 3 / 4），说明缺什么并**获得许可后**自行补全，其余按默认值。
- **补全项必须留痕** —— 写进第 0 章「假设与待替换」，逐条列出。
- **纯音乐专辑**额外问两项：**是否需要无缝成环的曲目**（第几首要loop）、**是否要留人声哼唱**（默认不要）。

## 四、专辑层七条硬规矩（与单曲层不同，专治「N 首撞车」）

**规矩 1：靠名词区分，不靠形容词。**

- 触发条件：写第 3 章（音色口径）、第 5 章（曲目表）、第 6 章（差异矩阵）。
- 硬性动作：区分维度只用 **拍号名、调式名、乐器名、BPM 数字、编制规模、音区**。
- 反例：✗ 第 2 首「比第 1 首更温暖」—— 形容词会被模型平均掉，写「温暖治愈」对每首都一样。
- 正例：✓ 第 2 首 `D dorian, 7/8, 84 BPM, cello + brushed drums, mid register`

**规矩 2：拍号与调式必须真的写进风格栏 token，不能只写在表格里。**

- 触发条件：写第 8 章每首的风格栏。
- 硬性动作：`7/8` 与 `dorian` 这两个词**必须出现在风格栏文本里**；否则那一轴是**名义轴**（表格里好看、生成时没生效）。
- 反例：✗ 表格写调式 D dorian，风格栏只有 `Mandarin folk, 84 BPM, acoustic guitar`
- 正例：✓ `Mandarin folk, 7/8, 84 BPM, D dorian, fingerpicked acoustic guitar + cello, …`

**规矩 3：纯音乐专辑 —— 不开「纯音乐」开关，靠歌词栏方括号编曲标签控制音乐流向。**

- 触发条件：用途是 OST / BGM，或用户说「不要人声」「纯音乐」。
- 硬性动作：
  1. **不开「纯音乐」开关**（Mureka 实测：打开后歌词栏被锁死，方括号编曲标签贴不进去）；
  2. 风格栏**第一个 token 写 `No vocals`**；
  3. 全篇（风格栏与歌词栏）**不得出现** `vocal / singer / humming / choir / ooh` 等人声词——
     写了等于反向指令，模型会用哼唱把人声补回来；
  4. **歌词栏方括号外一个字不留**（不留标题行、不留空行占位）；
  5. **段落标签不用** `Verse / Chorus / Bridge`（会招来演唱），改用
     `Intro → Loop A → Loop B → Loop A2 → Loop C → End`，**靠方括号里的编曲描述写音乐流向**
     （例：`[Loop B – 鼓组进，加入低八度贝斯，弦乐垫转亮]`）。
- 反例：✗ 打开纯音乐开关 + 歌词栏写满编曲标签 → 标签贴不进去，音乐流向失控
- 降级路径：仍出哼唱时按顺序做三件：删光人声词并把 token 简化到 4–7 个 → 换更纯器乐的流派词
  （`ambient / cinematic` 比 `pop / soul` 稳）→ 加一条 `no vocals, no humming, instrumental only`。
  三件做完仍出，如实告知并建议换流派方向，**不要在同一版上无限重试**。

**规矩 4：需要无损成环的曲目，四个词一起写。**

- 触发条件：用户要求无缝循环 / 游戏 BGM 可长放。
- 硬性动作：风格栏写 `单数 BPM`（不许写区间）+ `seamless loop` + `no fade in` + `no fade out`，
  并在 `[End]` 标签写「回到开头的和弦与织体、干净切断」。
- 纪律：**不许承诺「这条提示词直出无缝循环」** —— 无缝是素材 + 用户自己裁到整数小节 + 接缝交叉淡化做出来的。

**规矩 5：N 首 BPM 必须全不同。**

- 触发条件：写第 5 章与第 6 章。
- 硬性动作：N 首 BPM 互不相同，且**分散在至少 3 个速度区**（慢 ≤75 / 中 76–100 / 快 ≥101）。
- 反例：✗ 6 首全是 `88 BPM` —— 听感上会像同一首歌的 6 个段落。

**规矩 6：任意两首最多 2 根轴相同（唯一例外：序章 × 收尾）。**

- 触发条件：写第 6 章（差异矩阵）。
- 硬性动作：以 **拍号 / 调式 / 主奏乐器 / 编制规模 / 音区 / BPM 区间** 为 6 根轴，
  两两比对，同轴数 **>2 即为撞车**，必须改掉其中一首。
- **★ 唯一例外**：**序章 × 收尾**是**有意做成呼应**的（同一件乐器、不同和声），
  这两首的相同轴上限放宽到 **4 根**；超过 4 根照样判撞车，相同轴达 3 根时给 WARN 提示「呼应过头」。
  **其余所有曲目对一律 ≤2，没有第二个例外。**
- 反例：✗ 两首都是 `4/4 + A minor + 指弹木吉他 + 三人编制 + 中音区`
- 正例：✓ 第二首换 `7/8 + D dorian + 大提琴主奏 + 五人编制 + 低音区`
- 为什么要有这一条例外：呼应式收尾天然要复用序章的主奏乐器，
  若不给它单独上限，「收尾回到序章的编制」这条结构纪律与「≤2 根轴」就会**互相打架**。

**规矩 7：每首必附封面提示词，且必须点名曲名与留白位置。**

- 触发条件：写第 8 章每首。
- 硬性动作：每首附一段封面提示词，其中**必须出现 `封面文字：<曲名>`**、字体写「纤细手写体」、
  并**指定画面哪一侧留白放字**（例「右侧三分之一留白，竖排」）。
- 反例：✗ 只写「一张忧郁的封面」—— 没有文字、没有字体、没有留白，用户拿到图才知道要自己加字。

## 五、专辑结构与差异矩阵（怎么排才不塌）

### 5.1 结构：序章 + 分组 + 收尾

- **序章 1 首**：最短、最少编制、只留 1–2 件乐器，主题是「把门打开」。
- **主体分组 2–3 组**：每组一个共同基底（同一编制家族或同一调式家族），组内靠**拍号与音区**变化。
- **收尾 1 首**：回到序章的编制，但情绪已变（同一件乐器 + 不同和声）——这是「专辑感」的主要来源。
- **纪律**：收尾首与序章首的相同轴 **≤4 根**（规矩 6 的唯一例外），但 **BPM 数字必须不同**；
  相同轴达 3 根时收一收 —— 呼应过头就听不出「同一张专辑的两个极端」了。

### 5.2 差异矩阵：先排轴，再排值

排一张 N × N 的对照（对角线空），逐对填「相同轴数」。做法：

1. 先给每首**分配 6 根轴的值**（第 5 章曲目表就是这张表）；
2. **先保证每根轴上的值分布均匀**（6 根轴 × N 首，每轴至少 2 个不同值）；
3. 再两两比对，同轴 >2 的对，**优先改「主奏乐器」与「音区」**（这两轴对听感影响最大、最好换）；
4. 改完**重算全表**，不许只改一处就交付。

### 5.3 拍号与调式怎么配（口径，不是审美）

- **拍号给律动，调式给色彩。** 想要「往前推但不慌」→ 拍号用带增拍的 `7/8`；想要「稳、可以停住」→ `4/4`；想要「摇」→ `6/8` 或 `12/8`。
- **调式给明暗**：大调 / ionian 亮，小调 / aeolian 暗，dorian / mixolydian 灰里有光（适合治愈但不煽情）。
- **配对纪律**：
  1. **同一首里，拍号与调式不许互相抵消**（例：`6/8` 摇篮感 + 大调 = 明亮摇篮，可以；
     `6/8` + 三连音密集的快调式 = 自相矛盾，不行）；
  2. **一张专辑里，同一调式最多 3 首**（超过就成单一情绪的循环）；
  3. **每一对（拍号 × 调式）在第 8 章都要解释为什么这么配**，不许只给数字。

## 六、产物：三份，同一目录，单一真源

| # | 产物 | 内容 | 谁产出 |
|---|---|---|---|
| 1 | `<专辑名>-专辑规划-<风格版>.md` | 主文档，章节骨架见第七节 | `build_album.py` 渲染 |
| 2 | `<专辑名>-粘贴清单-<风格版>.md` | 每首三段可直接复制的文本，**全部包在 code tag 内** | `build_album.py` 渲染 |
| 3 | `build_album.py`（本技能脚本） | **唯一真源**：结构化数据 `ALBUM` + 渲染逻辑 | 手工维护 |

**为什么必须有第 3 份**：主文档与粘贴清单里都有曲目表、风格栏、BPM。
两份手写，改了曲目表忘了改清单，用户粘到的是旧版 —— 所以**两份 md 一律由脚本渲染，不许手写**。

**目录规则**：默认落在**当前工作目录下的 `<专辑名>/`** 文件夹；
专辑名含 `/ : * ? " < > |` 等非法字符时，目录名替换为 `-` 并在文末注明；
用户明确指定别的目录就照他的。

**渲染命令**：

```bash
python3 scripts/build_album.py --outdir ./<专辑名>
python3 scripts/build_album.py --check          # 只校验数据自洽，不写文件
```

## 七、主文档章节骨架（必须按此编号与顺序，一章不少）

```
0 结论先行
1 设计取舍
2 平台粘帖提示词和配置参数要点
3 音色口径 —— 风格锚点落到具体 token 上是哪几件事
4 专辑结构 —— 序章 + 各集分配
5 曲目表 —— 序号/曲名/时长/BPM/拍号/调式/主奏乐器/编制/音区/情绪
6 差异矩阵 —— N 首互不撞
7 ★ 拍号与调式 —— 分别解释这两行数字什么含义、为什么配对、配对的纪律
8 逐首提示词 —— 8.1 至 8.N，每首给：意象、结构、风格栏全文、歌词栏标签、封面提示词
附 校验记录
```

- **纯音乐专辑**的第 8 章：歌词栏一栏写方括号编曲标签（`Intro / Loop A / Loop B / Loop A2 / Loop C / End`），
  并在章首注明「本专辑不开『纯音乐』开关，靠方括号标签控制音乐流向」。
- **Suno 与 Mureka 的第 2 章与第 8 章字段不同**：Suno 是 `标题 + Style + Lyrics` 三段，
  Mureka 是 `风格栏（≤1000 字，英文 token）+ 歌词栏（≤5000 字，中文 + 标签）`双栏。
  **两套字段不许混写**，各平台的控件与坑见 `@references/platform-notes.md`。
- **第 7 章是两行数字的解释**，不是表格的重复：先说这两行数字分别是什么、怎么读，再说为什么配对、有什么纪律。

## 八、防幻觉（硬约束，优先级最高）

**本节优先于以上所有格式要求。**

1. **不承诺生成结果。** AI 音乐有随机性。禁止说「按这张专辑规划一定能出你要的效果」，
   改为「每首建议同一版生成 2–3 次挑一版；整张专辑的统一性靠的是规划，不是靠一次生成」。
2. **不编造用户没给的事实。** 专辑名、主题、集数、锚点、曲目名都用用户给的；
   意象可补，**具名实体、真实事件、真实地点、真实年份一律不编**。
3. **不编造参考作品。** 提到锚点只写风格特征，**禁止**编造某作曲家某年某专辑。
4. **信息补全与规则偏离都要标注。** 分两类写进第 0 章：
   - **补全的**（你替用户定的集数、锚点、默认听感）逐条列出，**禁止**当成用户说的；
   - **偏离的**（你有意不按某条规矩执行）写明偏离了哪条 + 为什么。
5. **不编造界面参数。** 平台控件以实测为准；平台限制会随版本变，不确定就写「以你当前界面实际表现为准」。
6. **不确定就直说不确定。** 「这个拍号 × 调式的配对我没有把握，建议先生成一段试听再定」是合格输出。

**改判据先过自检（维护纪律）**：修改 `scripts/album_check.py` 或 `build_album.py` 的任何阈值或判定后，

## 十一、降级与跨轮次

- **用户说「你看着办」**：九项全走默认值（个人发行、6 首、治愈文风、安静留白不煽情、中文歌词），
  风格锚点按 3.2 的替代条款给一个可执行锚点，直接产出。**但整轮话题是游戏 / 视频 / 播客 / 展厅 / 专注 / 白噪音**
  时，默认改走**纯音乐 + 专辑**路径（规则 3）—— 不要自作主张递上一张带人声的专辑。
- **用户要的其实是「N 首各写一首歌」**：说清区别 —— 单曲技能给 N 个互不相关的提示词包，
  本技能给的是**一张专辑**：有共同音色、有结构、有差异矩阵、收尾与序章呼应。
  落点是专辑，但每首的最终提示词格式仍按单曲技能的产出标准。
- **用户嫌主文档太长**：可把第 3 章与第 7 章合并成一节，但**第 5 / 6 章不许删**（那是专辑层的全部依据）。
- **跨轮次**：用户说「第 3 首太慢」「序章换首曲子」时，**只改对应数据并重跑 `build_album.py`**，
  不要手改 md —— 手改就是漂移的起点。重跑后必须**重跑 `album_check.py`**，因为改 BPM 可能撞车。
- **目标平台不是 Suno / Mureka**：明确告知「本技能的字段口径是按这两个平台实测整理的，换平台要按该平台格式改写」，
  不要原样照搬。

## 十二、反模式禁止清单

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | N 首各写各的，没有共同音色锚点 | 放在一起像同一台机器出的货，不是一张专辑 |
| 2 | 用形容词区分曲目（「更温暖」「更安静」） | 形容词会被模型平均掉，对每首都一样 |
| 3 | 拍号调式只写在表格、不进风格栏 token | 那一轴是名义轴，生成时根本没生效 |
| 4 | N 首 BPM 相同或写同一个速度区间 | 听感上是同一首歌的 N 个段落 |
| 5 | 差异矩阵只写「本专辑 N 首互不撞」不逐对比对 | 没人看着的声明等于没写；撞车了也发现不了 |
| 6 | 纯音乐专辑写「打开纯音乐开关」 | 实测打开后歌词栏锁死，方括号编曲标签贴不进去 |
| 7 | 纯音乐段落标签用 Verse / Chorus / Bridge | 会招来演唱，人声幻觉的主要来源 |
| 8 | 器乐风格栏里留着 `soft female vocals` | 等于反向指令，模型会用哼唱把人声补回来 |
| 9 | 循环曲目写 `fade out` 或 BPM 区间 | 尾部渐弱让循环点接不上；区间会让循环点落在小节中间 |
| 10 | 承诺「按这张规划直出无缝循环 / 一定出你要的效果」 | 无缝靠后期裁切，拍胸脯就是不诚实 |
| 11 | 封面提示词只写画面、不点名曲名与留白位置 | 用户拿到图才知道要自己加字 |
| 12 | 主文档与粘贴清单各手写一份 | 改了一处忘了另一处 = 用户粘到旧版（必须由脚本渲染） |
| 13 | 曲名没定就编 N 个名字直接跑全篇 | 用户多半要改，改了就得整篇重排 |
| 14 | 提示用户去调「时长 / 版本数 / 人声参数」 | **实测面板里没有这些控件**，会让人白找 |
