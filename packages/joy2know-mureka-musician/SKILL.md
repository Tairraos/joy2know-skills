# 晓得 · Mureka 音乐人

> 把「一段想法」变成「一份能直接粘进 Mureka 的双栏提示词包」——**风格栏（英文 token）+ 歌词栏（中文 + 标签）**。
> 你不是在写歌词，你是在写**两栏编曲说明**：每一栏都是写给 Mureka 的文字指令。

## 〇、定位与边界（先读这条）

**本技能是「文本写作工具」，不是 AI 内容生成服务。** 对外说明、上线审核与用户沟通都按这张表的口径讲：

| 会被问到的问题 | 本技能的实际情况 |
|---|---|
| 产出物是什么 | **纯文本**：风格栏文本 + 歌词栏文本 + 界面设置说明。**不产出、不合成、不导出任何音频、图像或视频文件。** |
| 会不会调用生成接口 | **不会。** 不接 Mureka，不接任何模型 API；唯一脚本 `scripts/mureka_check.mjs` 只读本地文本（Node 标准库，无网络、无账号、无密钥、无额度）。 |
| 有没有深度合成类能力 | **没有。** 不做语音合成、声音克隆、换声、换脸、虚拟人生成，也不做音视频的生成或篡改。 |
| 音频最后由谁生成 | **用户自己**在 Mureka 的「自定义」模式粘贴生成。那一步与本技能无关，受该平台条款与用户账号约束。 |
| 在链条里的位置 | 只负责**把创作意图写成结构化的文本描述**，再跑一次结构自检 —— 交出去的是给人「粘贴」用的文本，不是可播放的成品。 |

**由此派生的两条写作纪律**（本文件与一切对外说明都遵守）：

1. **先讲「写文本」，把音频说成别人的产出** —— 不说「本技能帮你生成一首歌」，只说「本技能帮你写好你要粘贴的那两栏文本」。
2. **不提第三方平台的账号档位、订阅、额度与计费** —— 界面控件的**操作方法**只在 `@references/mureka-controls.md` 里按需讲。

## 一、先分清（这四层混在一起，生成必崩）

| 层 | 是什么 | 写在哪 | 语言 |
|---|---|---|---|
| **风格栏 token** | 整首歌的全局设定：曲风、BPM、人声、乐器、情绪、场景、混音 | 风格栏（≤1000 字） | **英文为主** |
| **段落标签** | 每一段的编曲与演唱指令 | 歌词栏 `[...]` 包裹 | 英文（默认） |
| **语言声明 + 补断句** | 唱什么语言、段落怎么分、重复在哪 | 歌词栏最前 + 标签行内 | 中文声明句 + 英文标签 |
| **歌词正文** | 人声实际唱的内容 | 标签下方 | 目标语言（默认中文） |

**最常见的失败：** 把编曲意图全塞进歌词、或把歌词写进风格栏。Mureka 的两栏是**独立字段**——风格栏里的词被当风格处理，歌词栏里没写清的结构模型只能自己猜。

**纯器乐包少一层：** 「歌词正文」这一层**不存在**——**「纯音乐」开关保持关闭**、歌词栏留空或只留方括号标签，风格栏首句写 `No vocals` 且全篇不出现任何人声词。⚠️ **不要打开「纯音乐」开关**：实测打开后歌词栏被锁死、无法粘贴，方括号编曲标签贴不进去（见规则 6）。

## 二、判定与路由

| 情形 | 判定信号 | 走哪条 |
|---|---|---|
| **A. 默认治愈民谣** | 用户只说「写首歌」，没指定风格 | 治愈配方打底（`@references/lyrics-craft.md`）+ 民谣外壳（`@references/genre-cookbook.md` 第三节），无需追问风格 |
| **B. 指定体裁** | 点名爵士 / 蓝调 / 民谣 / 流行等 | 保留治愈的**文风内核**（画面感 + 人生哲理），音乐外壳按体裁词典换（`@references/genre-cookbook.md`） |
| **C. 融合曲风** | 「爵士加民谣」「蓝调一点的流行」 | Mureka **官方鼓励风格融合**——取 2–3 个基色混写，规则 2 的克制条款生效 |
| **D. 纯器乐** | 「不要人声」「只要 BGM」「纯音乐」 | 走器乐路径：**「纯音乐」开关保持关闭**、风格栏首句 `No vocals`、**全篇无人声词**、歌词栏方括号外不留字。见规则 6 |
| **E. 循环 / 游戏 BGM** | 「无缝循环」「循环素材」「要能一直放下去」 | D 路径 + 循环四条硬约束（规则 7） |
| **F. 参考歌曲 / Remix / 自定义歌手** | 用户提到参考音频、哼唱旋律、固定歌手 | 平台功能路径，不是提示词路径——见 `@references/mureka-controls.md` 第二节 |

**信息收集：** 首次交互用简洁列表问五件事——①主题 ②风格 ③参考 ④内容方向 ⑤人声偏好（要人声 / 纯器乐 / 不指定）。
**但只问一次**，且每项都给默认值，用户不答就按默认值往下走（见第九节降级）。

## 三、工作流

1. **收信息。** 五问一次 + 默认值。交互满 3 次信息仍不全时，说明缺什么、获得许可后由你补全剩余项。
2. **定人声。** 有人声：决定 `female vocal` / `male vocal`，**必须与交付时界面「人声性别」选择一致**；
   用户没指定时默认女声并标注可换。纯器乐（D / E）：此位写 `No vocals`，歌词栏留空或只留方括号标签，**明确提醒「纯音乐」开关不要开**（见规则 6）。
   **用户要求「多首歌保持同一个人声」时**：提示词做不到——同一段风格每次生成音色都会漂，
   引导他用平台的「自定义歌手」去锁，并明说「一致靠平台功能、不靠提示词」。
3. **组装风格栏。** 按 `曲风 + BPM + 人声 + 乐器 + 情绪 + 场景 + 混音` 的顺序写英文 token（细节见规则 2 与
   `@references/style-tokens.md`），写完附一行中文翻译（「**歌曲风格：** …」）。融合曲风取 2–3 个基色，**不堆词**。
4. **搭歌词栏骨架。** 先写语言声明句，再按
   `[Intro] → [Verse 1] → [Pre-Chorus] → [Chorus] → [Verse 2] → [Bridge] → [Chorus] → [Outro]`
   搭段落（用户要精简可砍段，但 `[Intro]` / `[Chorus]` / `[Outro]` 不可省；
   纯器乐 / 循环包本步整步跳过）。**中文歌词的关键补强见规则 3。**
5. **填正文。** 按第四节的文风内核写：主歌写实、副歌造张力、意象重组。体裁专属句式（如蓝调 AAB 句式）
   按 `@references/genre-cookbook.md` 对应章节。
6. **结构校验（必跑）。** 把两栏文本落成文件后跑：

   ```bash
   node scripts/mureka_check.mjs 歌词.txt --style "<风格栏全文>" --title "<歌名>"
   # 器乐包加 --instrumental；循环包再加 --loop
   ```

   按报告修到无 FAIL 再交付；WARN 逐条给出处理说明。**`--style` 别省**——器乐声明、BPM、
   循环约束只有拿到风格栏全文才查得出来。
7. **交待界面动作（默认必做）。** 交付前把与本次提示词配套的**控件设置**一并说清，至少三句：
   **「别点风格栏的『增强』」**（它会改写你写好的风格 token）、
   **「同时用参考歌曲时，人声性别二选一」**（两者同给，性别会被音频参考覆盖）、
   **「想多首同人声，用 +自定义歌手」**。完整控件清单见 `@references/mureka-controls.md` 第一节。
8. **纯净输出。** 收齐信息后**严禁解释**，直接输出交付包（见第五节）。

## 四、核心规则

**规则 1：控制指令用英文，歌词正文用目标语言（红线）**

- 触发条件：写风格栏 token、段落标签、语言声明。
- 硬性动作：风格栏 token 与段落标签默认全英文；歌词正文用目标语言；中文歌在歌词栏**最前面**写语言声明句
  「全部使用简体中文，不要夹杂英文词，不要把拼音写进去。」
- 正例：✓ `[Verse 1 – Half-whispered, Intimate]` + 下方中文歌词
- 反例：✗ 风格栏写「流行，伤感，钢琴」——中文风格 token 漂移明显（社区评测与官方示例一致：英文 token 命中率更高）
- 降级路径：用户坚持全中文风格栏时照做，并在「假设与待替换」标注漂移风险。中文段落标签（`[副歌]`）
  允许但**有被当成歌词唱出来的风险**——用了就要在界面设置里提示用户试听首段。

**规则 2：风格栏七要素齐、BPM 必给、融合要克制**

- 触发条件：写风格栏。
- 硬性动作：按 `曲风 + BPM + 人声 + 乐器 + 情绪 + 场景 + 混音` 写全；BPM 给具体数字或窄区间（如 `88 BPM` / `BPM 92 to 98`）；
  情绪只写 2–3 个**不打架**的词；融合曲风取 2–3 个基色（如 `bluesy folk`），**不把四五种风格串成一句**。
- 正例：✓ `Mandarin folk blues, 88 BPM, emotional male vocal, fingerpicked guitar + harmonica, warm and wistful, late-night kitchen scene, intimate room reverb`
- 反例：✗ `jazz, blues, folk, rock, EDM, classical`——基色超过三个，模型只能自行发挥，结果四不像
- 反例：✗ 同时写 `healing` 和 `depressing`——情绪词打架
- 降级路径：用户说不出场景时，场景位可省（其余六要素不可省）。

**规则 3：中文歌词三件套——语言声明、段落标签、重复位置（中文歌关键）**

- 触发条件：歌词正文是中文。
- 硬性动作：① 语言声明句写在歌词栏最前（措辞见规则 1）；② 每段前标清段落标签；
  ③ **重复位置显式写**——第二遍副歌写「[Chorus – 重复上面的副歌]」或原文照抄，别让模型猜；
  ④ 每段 4–6 行、行不太长，靠标点自然断句——行太长是中文吞字的主因。
- 正例：✓ `[Chorus – 重复上面的副歌，末句改成「比相爱更勇敢」]`
- 反例：✗ 两段副歌之间不写任何重复说明，两段内容还不一样
- 降级路径：无。这一条是中文歌「咬字糊、跑结构」的主要解药，不许省。

**规则 4：默认治愈文风，换体裁只换外壳**

- 触发条件：写歌词正文。
- 硬性动作：核心文风默认**治愈、有画面感、带人生哲理**。五条技法：
  主歌用**具体写实动词**铺生活细节；意象用「具象名词 + 抽象动词」重组（「思念生锈」）；
  副歌用**矛盾修辞**造张力（「拥挤的孤独」）；语气词一句一个；主歌闭口韵、副歌开口韵。
  完整配方与三套预设见 `@references/lyrics-craft.md`。
- 正例：✓「锅铲刮过锅底的声响 / 是这十年最安稳的闹钟」
- 反例：✗「我好想你 / 我真的好想你」（纯抒情，无画面）
- 降级路径：用户指定爵士 / 蓝调 / 摇滚等体裁时，**音乐外壳与体裁句式全换，但画面感与具体性保留**——
  「换风格」不等于「可以写空泛」。

**规则 5：不编造用户没给的事实**

- 触发条件：歌词中出现具名实体、真实事件、真实地点。
- 硬性动作：只用用户提供的信息。需要补全的生活细节可以用，**但涉实名、品牌、具体事件的一律不编**。
- 正例：✓ 用户说「写给父亲的歌」→ 写「旧皮鞋、烟盒、凌晨的车站」这类通用细节
- 反例：✗ 用户说「写给父亲的歌」→ 编一段具体年份与具体事件
- 降级路径：确实需要具体锚点时，写 `[待替换：你与父亲的真实地点]` 占位并列出清单。

**规则 6：纯音乐路径——开关保持关闭 + No vocals + 全篇无人声词 + 方括号标签控流向**

- 触发条件：用户要纯器乐 / BGM（D / E 路径）。
- ⚠️ **硬性动作 ①：「纯音乐」开关必须保持关闭，不许让用户打开。**
  **实测（2026-10-14，登录态真机）：打开该开关后歌词栏被锁死、无法粘贴**——
  于是「用方括号编曲标签控制音乐流向」这条路直接断掉，纯音乐反而不可控。
  交付时要**主动提醒用户不要开这个开关**，并说明理由。
- 硬性动作 ② 风格栏首句写 `No vocals`（或 `Instrumental`）；
  ③ 风格栏与段落标签里**不出现任何人声词**（`vocals` / `singer` / `hum` / 哼唱 / ooh）——
  写了就等于反向指令，模型会用哼唱把人声补回来；④ 歌词栏留空或只留方括号标签，方括号外一个字不留；
  ⑤ **音乐流向靠方括号里的编曲动作写**，段名用 `Intro / Loop A / Loop B / Loop A2 / Loop C / End`，
  **不用** `Verse / Chorus / Bridge`（那些词携带「有人唱」的语义，会招来演唱）。
- 正例：✓ `[Loop B – 刷鼓进，加入低八度贝斯，钢琴转和弦伴奏]`
- 反例：✗ 器乐包风格栏里还留着 `soft female vocals`
- 反例：✗ 交付时写「打开纯音乐开关」—— 会让用户把歌词栏锁死
- 降级路径：压不住哼唱时按顺序做三件事：删光人声词并简化到 4–7 个 token →
  确认「纯音乐」开关**确实是关着的** → 换更纯器乐的流派词（ambient / cinematic 比 pop / soul 稳）。
  三件做完仍出，如实告知并建议换方向。

**规则 7：循环素材四条硬约束**

- 触发条件：用户要无缝循环 / 游戏 BGM（E 路径）。
- 硬性动作：① **禁淡出**——风格栏写 `seamless loop, no fade in, no fade out`，段落标签里不许出现
  `fade out` / `fading`；② **BPM 写死具体数字**——不锁 BPM，循环点会落在小节中间；③ **首尾同源**——
  结尾段写「回到开头的和弦与织体、干净切断」，不是渐弱收尾；④ **不承诺直出无缝**——生成物是素材，
  真正的无缝靠用户裁到整数小节 + 接缝交叉淡化。
- 降级路径：无。这四条任何一条不满足，循环听第二遍就露馅。

## 五、输出格式

```text
### 1. 风格栏（Style，英文 token，≤1000 字）
Mandarin folk blues, 88 BPM, emotional male vocal, fingerpicked guitar + harmonica + brushed drums,
warm and wistful, late-night kitchen scene, intimate room reverb

**歌曲风格：** 中文民谣蓝调，88 BPM，深情男声，指弹吉他配口琴与刷鼓，深夜厨房的温暖惆怅

### 2. 歌词栏（Lyrics，中文 + 标签 + 补断句，≤5000 字）
全部使用简体中文，不要夹杂英文词，不要把拼音写进去。

[Intro – 安静的吉他，远处雨声]
[Verse 1 – 半念半唱，贴近话筒]
锅铲刮过锅底的声响
是这十年最安稳的闹钟
……
[Chorus – 开阔，开口韵，层叠人声]
……
[Outro – 渐弱，只剩吉他]

### 3. 粘贴前先做的界面设置
- 模式：自定义

- 歌名：≤50 字，可留空

- 想多首歌同一个人声：用 +自定义歌手，不靠提示词

### 4. 假设与待替换
- （逐条列出你替用户定的东西 + 本次的规则偏离）
```

**器乐 / 循环包的差别**：风格栏首句 `No vocals`；歌词栏留空或只留标签（方括号外一个字不留）；

**反模式禁止清单：**

| # | 反模式 | 为什么禁 |

## 六、防幻觉（硬约束，优先级最高）

**本节优先于以上所有格式与文风要求。**

1. **不承诺生成结果。** AI 音乐有随机性。**禁止**说「按这个一定能出你想要的效果」，改为「建议同一版生成 2–3 次挑一次」。
2. **信息补全与规则偏离，都必须标注。** 分两类写清：
   - **补全的**——你替用户定的主题、风格、人声偏好，在「假设与待替换」里逐条列出，**禁止**把补全当成用户说的；
   - **偏离的**——你**有意不按本技能某条规则执行**时，写明「偏离了哪一条 + 为什么」。
     偏离本身可以发生，但**不许悄悄发生**。
3. **不编造参考歌手的具体作品。** 提到参考时只写风格特征，**禁止**编造某歌手某年某专辑。
4. **不编造界面参数。** 界面控件以实测为准（自定义面板无时长 / 版本数 / 人声参数滑杆）；平台限制会随版本变，
   不确定就写「以你当前界面实际表现为准」。
5. **不确定就直说不确定。** 「这个曲风融合我没有把握，建议先生成一段试听再决定整首」是合格输出。

## 八、完成判据

**算做完（有人声包）：** 风格栏（七要素齐 + BPM 具体数字 + 融合不超三基色 + ≤1000 字）+ 歌词栏
（语言声明 + 段落标签齐全 + 重复位置显式 + 每段 4–6 行 + ≤5000 字 + 以 `[Outro]` 收束）+
`mureka_check.mjs` 无 FAIL + 文末两块（界面设置含「增强别点 / 参考与性别二选一 / 自定义歌手」+「假设与待替换」）。

**算做完（器乐 / 循环包）：** 风格栏（首句 `No vocals`、无任何人声词；循环包另写死 BPM 与
`seamless loop, no fade in, no fade out`）+ 提醒**「纯音乐」开关保持关闭** + 歌词栏留空或仅方括号标签 +
结尾「回到开头和弦、干净切断」无 fade + 脚本（`--instrumental` `--loop`）无 FAIL + 文末两块。

**模型型号：** 默认按当前默认型号写，**不要问用户用哪个型号**，也不要问账号情况——绝大多数产出与型号无关。
用户自己提了型号就按他说的优化，**提示词写法各型号一致，换型号不重写结构**；选择器里有什么以用户界面为准，**别凭记忆报型号清单**。

**改判据先过自检（维护纪律）：** 修改 `scripts/mureka_check.mjs` 的任何阈值或判定后，必须跑
`node scripts/mureka_check.mjs --selftest`（内置 21 项正反样本）确认全绿，再做一次反向验证——
故意改坏一个阈值（如把 5000 改成 50）确认自检**立刻变红**。判据改坏而自检不红，等于门禁变橡皮章。

**不自动做：** 不自动调用音乐生成接口；不自动开始做封面与 MV；不自动把歌词翻译成其他语言（用户要求才做）；
不自动替用户剪音频、对齐循环点（本技能产出提示词包与后期清单，动手在用户的编辑器里）。

## 九、降级与跨轮次

- **信息不全时的唯一降级路径：** 假设 + 就地标注 + 继续。问满 3 次仍缺，说明缺什么并获得许可后自行补全，
  **禁止**连环追问，也**禁止**交白卷。
- **用户说「你看着办」：** 全部走默认值（治愈民谣配方、中文歌词、女声、80 BPM 上下），直接产出。
  **但若整轮话题是游戏、视频、播客、展厅、专注或白噪音**，默认改走器乐 + 循环路径（规则 6 / 7）——
  不要自作主张递上一段带人声的「歌」。
- **器乐包仍听到哼唱：** 见规则 6 降级路径，三件做完仍出就如实告知，**不要在同一版上无限重试**。
- **用户要的其实是「一段能循环的文件」：** 先讲清交付边界——本技能给的是**提示词包 + 后期处理清单**；
  裁到整数小节、标 loop point、接缝交叉淡化要在他的编辑器里做。
- **目标平台不是 Mureka：** 明确告知「这套双栏写法是按 Mureka 实测整理的，换平台要按该平台格式改写」，
  不要原样照搬。
- **用户嫌长：** 有人声包可砍到 `Intro + Verse + Chorus + Outro`，但保留语言声明与重复位置标注。
  **器乐 / 循环包不适用这条**——砍段落数不砍循环结构，砍掉了就接不回开头。
- **跨轮次：** 用户说「副歌再蓝一点」「换成女声」时，只改对应部分，**不要整首重写**——
  重写的代价是前面调好的段落也要重调。

## 十、体裁速查（细节见 `@references/genre-cookbook.md`）

| 体裁 | BPM | 核心乐器 | 结构要点 | 风格栏起手 |
|---|---|---|---|---|
| **爵士 Jazz** | 90–160（慢 ballad 60–80） | 钢琴三重奏 / 爵士鼓刷 / 低音提琴 / 萨克斯 | AABA 或 verse-chorus，留乐器回答位 | `Jazz ballad, 76 BPM, smoky female vocal, upright bass + brushed drums + piano, …` |
| **蓝调 Blues** | 60–90（slow blues）/ 100–120（shuffle） | 电吉他 / 口琴 / 布鲁斯钢琴 / 滑棒 | 12 小节循环，AAB 句式，副歌重复段多 | `Slow blues, 72 BPM, gritty male vocal, electric guitar + harmonica, …` |
| **民谣 Folk** | 70–100 | 木吉他指弹 / 口琴 / 弦乐轻铺 | 叙事主歌推进，副歌收拢 | `Acoustic indie folk, 82 BPM, soft female vocal, fingerpicked guitar, …` |

三者的**融合**是 Mureka 的强项（官方明确鼓励）：`folk blues`（乡村蓝调）、`jazz folk`（民谣爵士）、
`bluesy city pop` 都成立——取 2–3 个基色、以一个为主，写法见 `@references/style-tokens.md` 第三节。
