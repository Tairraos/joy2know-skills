# 晓得 · 别解

> **产出是一句话加一份 SVG 文本。** 不生成图片文件、不调用任何生成接口、不带账号与密钥。

## 〇、定位与边界

**「别解」是一个现成的修辞格**：临时赋予一个词以它原本没有的新义，用来打趣或讽刺。
（定义见 `@references/biejie-patterns.md`；它是谜语、笑话、广告标题的常用手法。）

三条边界，先立住：

1. **别解不是「更新的正确解释」。** 正解的对立面是「误解」，别解的对立面是「**正解**」——
   我们坦白自己只是另一种说法，**不跟词典争位置**。所以卡片里不写「正确」「其实」「真正的意思是」。
2. **别解不是百科。** 出现的数字、年份、人名、法规号、机构名，必须来自用户给的信息或可查证事实；
   查不到就不写。**为了一句漂亮话而编一个事实，是本技能最严重的失败。**
3. **不适用于**：正经词典释义与词源考证、学术定义、需要真实数据的图表、海报与 UI 设计稿、
   把词条翻译成其他语言。遇到这些，直说「这不该用别解」，给正经答案。

## 一、要解决什么病

随手给一个词「写点有意思的」，最常见的三种垮法：

1. **只是同义改写。**「内卷就是过度竞争」——那是词典释义换了说法，不是别解，没有新义。
2. **只有机智，没有落点。** 抖了个机灵，但读完不知道在说什么词。
3. **配图是装饰。** 画个圆、画条波浪线、撒几个几何块——删掉完全不影响理解，说明它没在承担信息。

本技能的产出标准只有一条：**读完那句释义会「咯噔」一下，再看图会明白那句为什么成立。**

## 二、判定路由

动手前先判两件事：**这个词能不能别解**、**这次要做多少**。

### 2.1 能不能别解（四档）

| 档 | 词的形态 | 处置 |
|---|---|---|
| **A 能别解（首选）** | 抽象名词、职业词、社会热词、行业黑话、缩写词 | 走完整流程，出卡 |
| **B 能别解但需克制** | 专业术语（法律 / 医学 / 技术） | 只做**返源式**字面别解，不牵强附会、不做人身讽刺 |
| **C 只给释义不出卡** | 用户要的是真解释、或词太生僻没有公认用法 | 给正经释义，说明「这个词没有公共语境，别解会变成瞎编」 |
| **D 不做** | 五类硬红线（逐条全文见 `@references/biejie-patterns.md` §三）：真人姓名与在世具体个人、民族 / 地域 / 性别 / 职业群体的贬称、灾难与伤亡、正在审理的案件、只能靠贬损某群人才成立的笑话 | 直接说明不适用，换个词 |

**D 档是硬红线。** 别解的靶子只能是**词与概念**，不能是**人**。同一个词若只能靠贬损某群人才好笑，那就不做。

### 2.2 这次做多少

| 用户要的 | 产出 |
|---|---|
| 「来一个别解」/ 直接给一个词 | 释义一句 + 卡片（默认出卡） |
| 「只要解释」「不用做图」 | 只给释义；**不要劝他加图** |
| 「做个卡片／要能下载的」 | 卡片（默认竖版 `poster`） |
| 给了词 + 明确用途（发朋友圈、做专栏配图） | 出卡，并把 `--palette` 固定下来，便于同系列统一 |

## 三、工作流（五步，顺序不能换）

```
1 定类型   → 判 A/B/C/D（§2.1）。C 或 D 到此为止，走 §九 降级。
2 选别解式 → 返源式 还是 附会式（@references/biejie-patterns.md 第二节）
3 写释义   → 一句话，20–40 字。写完读一遍：删掉它，这个词的意思还在不在？还在 = 没写成别解，重写。
4 定图解   → 先写下「图里的 X = 释义里的 Y」对应表（§四.2）。凑不出 2 条就不画。
5 出卡     → 用 scripts/card.mjs 排骨架，图解片段填进槽位（§五）
```

**第 3 步是这一步的验收：** 释义必须能一句话说完。要写两句才说清，说明还没抓住本质。

## 四、核心规则（四件套）

### 四.1 释义怎么写（返源 / 附会）

| 式 | 做法 | 例（示范写法，不是唯一答案） |
|---|---|---|
| **返源式** | 把词的整体义拉回**字面义相加** | 甲方 →「甲方，是一个动词：用一笔预算，买断另一个人对美的定义权。」 |
| **附会式** | 借词的**多义或谐音**，牵强地接到另一个意思 | 打工人 →「用青春换房贷的勇士」 |

两条写法纪律：

- **不写「其实」**：别解不是揭露真相，是另起一个读法。「其实」一出口就变成了声称事实。
- **不写结论式金句**：结尾不要「这就是 X 的本质」。落到具体动作或画面上，比落到名词上更有力。

### 四.2 图解怎么写（本节是本技能最容易糊弄的地方）

**先写对应表，再动手画。** 三行以内：

```
图里的 自环箭头   = 释义里的「每改一版，需求就多一条」
图里的 断口与虚线 = 释义里的「口径调整」
（第三行留空 = 这一处不强行对应）
```

四条硬规矩：

1. **图里不允许出现释义中不存在的元素。** 画不出来就不要画——删掉图不影响理解，说明这张图本来就是装饰。
2. **凑得出 2 个对应就画 2 个**；凑不出 2 个就不画，只留文字。**宁可没有图，不要装饰图。**
3. **字形与线条不承载数值时，不许长得像图表。** 线条在上升、方块在变高，读者就会读成数据。
4. **同一张图只用一种关系表达方式。** 两种关系用实线 / 虚线区分，不用颜色区分（色觉障碍者读不出）。

什么时候**不画**：释义本身是单因单果一句话、或是纯态度没有结构。这两种情况画什么都是装饰。

### 四.3 语言行怎么写（三分支，不许含糊）

词条下方一行，固定格式 `English: <英文>  |  繁體：<值>`。**`<值>` 按三分支判定：**

| 情形 | 写什么 | 例 |
|---|---|---|
| 与简体**异形** | 直接给繁體字形 | `繁體：週報` |
| 与简体**同形** | 标「同形」 | `繁體：甲方（同形）` |
| **字母词 / 数字词** | 标「字母詞，繁簡同形」 | `繁體：字母詞，繁簡同形` |

**⚠️ 不许自己造「粤语说法」。** 模型遇到同形词时极容易编一个"看起来像香港话"的词来填满那一行。
**没有可查来源的粤语特有词一律不写**——同形就写同形。这一条比好看重要。

### 四.4 卡片硬约束

**由 `scripts/card.mjs check` 逐条可验（共 10 项）**：

- 每个图形元素**显式写 `fill` 或 `stroke`**，不依赖外部 CSS 类（类名不存在会退化成黑色）
- 一张卡**不超过 4 种颜色**（含底色）。马卡龙配色每套恰好 4 个：底色 / 墨色 / 弱化色 / 强调色
- 字号**不小于 11px**
- **不出现 emoji 当图标**；`<title>` 与 `<desc>` 必须有
- 不写 HTML 注释、不引外部资源（无 `http`、无 `url(`、无 `<script>`）
- **刊头固定「晓得·别解」**；页脚默认「一目晓得」——**卡片里不出现任何第三方作品名或作者名**

**脚本不校验、须人工把关的两条**：图解**节点 7–9 个**、**连线 ≤12 条**。
⚠️ `check` 回显里的「元素 N」是**整卡图形元素数**（含卡片外框与文字），**不等于图解节点数**——
不要拿它当这两条的判据（一张合规的 poster 卡「元素」通常是 8–15）。

## 五、输出格式

### 5.1 必须先给一句话

一句话结论在最前面，然后才是卡片。**只有图没有那句话，等于把理解成本推给读者。**

### 5.2 卡片由脚本排版，不要手写

```bash
node scripts/card.mjs render \
  --word 甲方 --pinyin "jiǎ fāng" \
  --en "Client / Party A" --trad-same \
  --def "甲方，是一个动词。" \
  --def "用一笔预算，买断另一个人对美的定义权。" \
  --diagram diagram.svg --caption "自环：每改一版，需求就多一条" \
  --out card.svg
```

- `--canvas poster`（默认）= 400×600 竖版，可下载可分享；`--canvas inline` = 680 宽横版，对话内预览用。
  **两套坐标由同一个脚本生成**，不要手工改坐标——手工改必然与另一套漂移。
- `--palette` 默认 `auto`：**按词条哈希取色**，同一个词永远同一个马卡龙色，不同词不同色。
  也可 `--palette sakura` 指定，或 `--palette random` 真随机。**同系列要统一就固定一个色名。**
- **图解片段里的四个占位符**会被替换成本次配色（**只写占位符，不要自带色值**，否则会和配色打架
  并突破 4 色上限）。片段坐标**以图解区中心为原点**书写，所以与画布宽度无关。
- 改完**必须跑一次 `node scripts/card.mjs check --in card.svg`**，`check` 不通过不许交。

四个子命令：`render`（出卡）· `check`（合规自检）· `palettes`（打印 8 套配色的键与色值）·
`selftest`（检查器自身的正反向用例，含**选色稳定性与分散度**及其反向对照，改动 `check` 或
选色逻辑后必跑）。全部参数与 10 项自检细则见 `@references/card-spec.md`。

### 5.3 交付形态

| 场景 | 给什么 |
|---|---|
| 对话内看 | 直接内联 SVG（`--canvas inline`） |
| 要能下载 / 分享 | `--canvas poster` 的 SVG；或包进单文件 HTML |
| 一次要一批 | 逐词出卡，**同一次会话固定同一个 `--palette`** |

## 六、防幻觉

**这一节的优先级高于上面所有格式要求。** 别解天然带着"已经想透了"的可信感，一旦里面混进假事实，用户几乎不会发现。

1. **释义里的每一个事实都要有出处。** 数字、年份、人名、法规号、机构名——来自用户给的、或可查证的；
   查不到就改写成不含该事实的说法。**推断要标「推断」。**
2. **图里每个元素都要能指回释义。** 指不回去的元素删掉。允许不画，不允许装饰。
3. **不确定的读音不标。** 拼音拿不准就留空（`--pinyin` 不传），**宁可没有这一行，不要标错音**。
4. **繁體拿不准就写「同形」**，不许编粤语说法（§四.3）。
5. **区分三种来源，必要时明说**：用户提供的 / 我查证到的（附来源）/ 我推断的（标注为推断）。

**反例：**

- ✗ 给「996」标了个拼音（数字词没有拼音），或给多音字只标一个音而不说明
- ✗ 释义里写「2024 年某平台数据显示…」，而用户没给、也无来源
- ✗ 图里画了一条上升折线，暗示"数据在涨"，而根本没有数据

## 八、完成判据

一份产出算完成，要**同时**满足：

- [ ] 释义一句话说完，20–40 字，且**不是同义改写**（把原词换成近义词就复述不出这句）
- [ ] 释义里没有一个查不到出处的事实
- [ ] 图解的对应表写出来了；**对应不上的地方没有硬凑**
- [ ] 语言行按三分支写对了；没有编造粤语说法
- [ ] `node scripts/card.mjs check --in card.svg` 返回 0
- [ ] 卡片里没有第三方作品名或作者名
- [ ] 输出顺序是「一句话 → 卡片 → 一句解读」，**不是甩一张图**

## 九、降级与跨轮次

- **判 C/D 档时**：说明理由 + 给正经释义或换个词的建议，**不要硬做一个别解**。
- **没有 node / 不能跑脚本**：按 `@references/card-spec.md` 的元素顺序手写 SVG，
  并逐条对照 §五 的合规清单自查；**明确告诉用户「本次未过 `check`」**（降级要留痕）。
- **用户嫌短/嫌长**：调释义长度只改字数，**不许靠加形容词**——加字要加在具体动作或画面上。
- **要连续出多条**：固定 `--palette`，保持刊头与骨架一致；**一次只给一条的完整产出**，不要堆一屏。
- **跨轮次**：上一轮已定的词、配色、系列名要沿用；用户没要求就不要换。
