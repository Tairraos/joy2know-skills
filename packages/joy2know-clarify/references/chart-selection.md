# 图种实现规范

本文件是 `joy2know-clarify` 的引用资料，回答"决定要画之后，怎么画得不难看、不误导"。

---

## 一、通用渲染约束（先读这一节）

### 1. 载体选择

| 场景 | 载体 |
|---|---|
| 对话内即时展示 | 平台内联可视化能力（SVG 或 HTML 片段） |
| 需要交付独立文件 | 单文件 HTML，样式与图形内联 |
| 平台不支持图形 | 降级为 Markdown 表格 / 缩进层级块 / 箭头文字链 |

**永远不要因为载体不可用而放弃结构。** 结构是主体，图是表现形式。

### 2. 尺寸与主题（平台内联 SVG）

- 画布按宽 680 设计，`viewBox` 从 `0 0 680 …` 开始，高度按内容自适应。
- **必须跟随当前 IDE 主题**：浅色主题用浅底深字，深色主题用深底浅字。禁止在浅色主题里用深色面板。
- **每个图形元素必须显式设置填充色**，不要依赖外部 CSS 类——类名在渲染环境里可能不存在，会退化成黑色。
- 文字与背景的对比度要足够；不要用浅灰字配白底。

### 3. 信息密度

| 项 | 上限 | 超出怎么办 |
|---|---|---|
| 一张图的节点数 | 7–9 个 | 拆成两张图，或合并同类 |
| 一个节点内的文字 | 12 个汉字 / 24 个英文字符 | 缩短，细节放到图后的文字里 |
| 一张图的箭头／连线 | 12 条 | 去掉弱关系，只留主干 |
| 并行分支 | 4 条 | 分层，或改表格 |

**图的目的是降低认知负担。节点一多，负担反而高于纯文字。** 超过上限就拆图。

## 二、各图种实现细则

### 1. 流程图（流程、步骤、时序）

- 节点用**方正矩形**，圆角控制在 4–8px。
- 方向统一：主流程从上到下或从左到右，**不要混用**。
- 判断分支用**菱形**，出口分别标注「是／否」。
- 步骤编号写在节点左上角或节点内前缀，便于文字里引用（"第 3 步"）。
- **少于 3 步不要画**，用"1 → 2 → 3"一行文字更清楚。

### 2. 树形图 / 层级块（层级、分类、归属）

- 同层节点**左对齐**，不要居中（居中会看不出层级）。
- 每层用**同一套配色**，用颜色区分层级，不要用颜色区分重要性。
- 层级超过 4 层时改用缩进文本，图会失控。
- **只有一层时不要画。**

### 3. 对比矩阵（对比、选型、优劣）

- 这是**表格**，不是图形。优先用 Markdown 表格。
- 维度（行）与对象（列）不要同时超过 5 个，否则表会宽到读不了。
- **给每个维度标注方向**（"越高越好" / "越低越好"），否则读者不知道优劣方向。
- 需要突出结论时，可在推荐项那一格加粗，而不是整行加底色。
- **只比 1 个维度时用文字**，表格是杀鸡用牛刀。

### 4. 容器图 / 结构图（结构、组成、包含）

- 用**嵌套矩形**表达包含关系，外框是"整体"，内框是"部分"。
- 部分的数量控制在 3–7 个。少于 3 个不画。
- 部分之间有交互时，用虚线连接并标注交互内容。

### 5. 图表（数量、趋势、分布）

- **红线：没有真实数据不画。** 不接受"示意性"的柱状图。
- 柱状图用于比较离散项；折线图用于连续趋势；饼图只在**各部分合计为整体**且**分片不超过 5 个**时使用。
- **坐标轴必须从 0 开始**（柱状图尤其）。截断纵轴是最常见的误导手法。
- 必须标注单位与数据来源（或"数据来自用户提供"）。
- 数据缺失时，在该位置标注"未提供"，**不要用 0 代替**。

### 6. 网络图 / 关系图（关系、依赖、影响）

- 节点用**圆形或圆角矩形**，避免与流程图的方正节点混淆。
- 有方向的依赖必须用箭头；无方向的关联用实线。
- 关系类型多于一种时，用**线条样式**区分（实线／虚线），不要用颜色区分（色盲不友好）。
- 节点少于 3 个、或方向说不清时不画。

### 7. 状态机图（状态、流转、生命周期）

- 状态用**圆角矩形**，初始状态用实心圆点，终止状态用双圈。
- 迁移线必须标注**触发条件**，没有条件的迁移线是无意义的。
- 状态少于 3 个时用表格。

### 8. 时间轴（时间、里程碑、排期）

- 时间刻度要**等距**（除非时间本身不等距，此时需明确标注）。
- 每个节点标注日期与内容，**两者缺一不可**。
- **只有 2 个时间点时用文字**（"从 A 到 B"）。

### 9. 因果链图（因果、推理链）

- 箭头从因指向果，**每段箭头标注机制**（"因为…所以…"），否则只是一个操作符，没有解释力。
- 因果链长度控制在 5 段以内。
- 存在多因一果时，把多个"因"画在左侧汇合，不要串成一条直线（那会暗示因果顺序，是错的）。
- **单因单果、一句话说得完时不要画**（"因为 A 所以 B"用文字即可），图只会稀释力度。

### 10. 位置示意图（空间、位置、布局）

- 需要方向参照（指北针或"上北下南"标注）。
- 距离不成比例时必须标注"非等比例示意图"。
- **本来就没有空间信息时不要画**：若"位置"只是顺序（第一步在哪、第二步在哪），那该用流程图或时间轴，不是位置示意图。

### 11. 类比示意图（抽象概念、心智模型）

- **必须先确认类比与本体的一一对应关系。** 对应不上的地方要在图里标出来（"此处类比失效"），否则类比会误导。
- 左右并列：左侧"本体"，右侧"类比物"，中间用对应线连接。
- 说不清对应关系时不要画，改用一段类比文字。

## 三、配色与排版

### 配色

- 一张图**不超过 4 种颜色**（含底色）。
- 用颜色表达**类别**，不用颜色表达**好坏**——表达好坏用形状、位置或文字标注。
- 语义色沿用常规认知：红＝风险／下降／警示，绿＝安全／通过／上升；**金融场景例外，遵循中国习惯（红涨绿跌）。**
- 不要用纯饱和色（#FF0000）大面积填充，用低饱和填充 + 深色描边。

### 文字

- 图内字号不小于正文的 0.75 倍。
- 中文用系统默认无衬线字体，英文与之匹配，**不要混用衬线体**。
- 节点内文字**不要竖排**。
- 图内不要出现 emoji 作为图标——用几何图形或纯文字标签。

### 图与文的关系

- 图前一句话：**引出**（"这三者的依赖关系如下"）。
- 图后一句话：**解读**（"可以看到 X 依赖 Y，因此 Y 必须先完成"）。
- **只有图没有解读，等于把理解成本推给读者。**

## 四、交付前检查

- [ ] 每个数字都有来源，或已标注"未提供"
- [ ] 没有为了美观补全的关系或层级
- [ ] 节点数、连线数在 3 节的上限内
- [ ] 配色跟随主题，文字对比度足够
- [ ] 图前有引出，图后有解读
- [ ] 对照**决策表第 5 列「什么时候别画」**（`SKILL.md` §四），确认这张图确实该画
