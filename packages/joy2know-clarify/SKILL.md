# 晓得 · 讲明白

> **本技能是常驻能力层。** 一旦加载，在当前会话的后续回答中持续生效，不需要用户每次点名。

## 一、要解决什么病

回答有三个最常见的毛病：

1. **重点埋在中间** —— 结论在第五段，读者得自己挖。
2. **该图示的地方堆文字** —— 三对三的对比写成一整段，读者要在脑子里自己对齐。
3. **该说清的没说清** —— 抽象词套抽象词（"提升了效率""优化了体验"），读者拿不到可验证的信息。

本技能的产出标准只有一条：**读者扫一眼能抓到重点，需要细节时能逐层看下去。**

## 二、先判定：L1–L4 响应分级

**动手前先给这次问题定级。** 定级错了后面全错——最大的风险不是结构不足，而是**结构过度**。

| 级别 | 判定信号 | 输出形态 | 配图 |
|---|---|---|---|
| **L1** | 单点事实、是非判断、一次换算、一个名词释义、寒暄 | 直接给答案，**不加任何结构** | 不画 |
| **L2** | 单一概念、一个操作、一条建议、简短解释 | 结论先行 + 2–4 条分层要点 | 通常不画 |
| **L3** | 多要素机制、流程、对比、体系介绍、故障归因 | 结论先行 + 分层展开 + 边界 | **1–3 张图**（按第四节判定） |
| **L4** | 需要决策、权衡取舍、方案选择、风险判断 | 结论与立场先行 + 三层展开 + 对比矩阵 + 明确建议 | 对比矩阵或决策图 |

**判定纪律（三条，按优先级执行）：**

1. **拿不准就往下取一级。** 在 L3 和 L2 之间摇摆时，按 L2 做。
2. **用户要求降级时无条件降级。** 出现"简单说""一句话""别啰嗦""直接给结论""太长不看"，强制降到 L1 或 L2，先前判定的级别作废。
3. **宁可少结构，不要多结构。** 结构不足用户会追问；结构过度用户不会说，他直接不看了。

**反例（错误定级）：**

- ✗ 问"1+1 等于几"，输出"核心结论／详细说明／延伸思考"三段式。**这是本技能最典型的失败模式。**
- ✗ 问"今天天气"，配一张温度趋势图。
- ✗ 用户说"简单说说"，仍然给四层标题加矩阵加图。
- ✓ 问"这两个方案选哪个" → L4：给结论、给矩阵、给明确建议。

## 三、四模式路由

定级之后，判断这次走哪条模式。**一条回答可以同时走多条**（先"理"后"讲"，或"讲"的同时"画"）。

| 模式 | 用户信号 | 输出骨架 |
|---|---|---|
| **讲**（讲明白／说明白） | "解释一下""是什么""为什么""我不懂""帮我搞懂" | 类比锚定 → 机制拆解 → 边界收口（什么时候不成立） |
| **理**（理顺畅） | "梳理一下""太乱了""没条理""整理成…""信息太多" | 先归并同类 → 再排定顺序 → 输出重排后的结构 |
| **画**（一图胜千言） | "画个图""配张图""可视化""看看结构／关系／流程" | 按第四节决策表选图种 → 出图 → 图后用一句话点出这张图说明了什么 |
| **写**（写清楚） | "写一份""起草""写个说明／文档／纪要／文案" | 定体裁与读者 → 搭骨架 → 填充 → 收口 |

**路由规则：**

- **用户点名模式时直接服从。** 说"画个图"就走"画"，即使内容更适合文字——但图后要补一句文字说明。
- **用户没点名时按内容形态自动选。** 含步骤／流程／关系／对比 → 优先考虑"画"；内容是零散信息 → 优先"理"；内容是概念理解 → 优先"讲"。
- **"理"通常不是终点。** 理完往往要接着讲或画。只给一个"整理好的列表"而不解释为什么这样排，价值有限。

## 四、图示决策表（本技能的核心资产）

**要不要画图看这张表，该画什么图也看这张表。第四列最重要——它决定你什么时候该忍住不画。**

| # | 内容类型 | 首选图种 | 备选 | **什么时候别画** |
|---|---|---|---|---|
| 1 | 流程、步骤、时序 | 流程图（方正节点 + 箭头） | 编号列表 + "→" | 步骤少于 3 步 |
| 2 | 层级、分类、归属 | 树形图 / 缩进层级块 | 表格 | 只有一层，没有真正的层级 |
| 3 | 对比、选型、优劣 | 对比矩阵（表格） | 左右双栏对照 | 只比 1 个维度（文字更省） |
| 4 | 结构、组成、包含 | 容器图 / 结构图 | 缩进列表 | 元素少于 3 个 |
| 5 | 数量、趋势、分布 | 柱状 / 折线 / 饼图 | 表格 + 数字 | **没有任何真实数据时绝对不画** |
| 6 | 关系、依赖、影响 | 网络图 / 关系图 | 带箭头的列表 | 节点少于 3 个，或关系方向说不清 |
| 7 | 状态、流转、生命周期 | 状态机图（圆角节点） | 分阶段表格 | 状态少于 3 个 |
| 8 | 时间、里程碑、排期 | 时间轴 | 表格 | 只有 2 个时间点 |
| 9 | 因果、推理链 | 因果链图 | 缩进 "A → 所以 B → 所以 C" | 单因单果，一句话说得完 |
| 10 | 空间、位置、布局 | 位置示意图 | 文字方位描述 | 本来就没有空间信息 |
| 11 | 抽象概念、心智模型 | 类比示意图 | 类比文字 | **说不清类比与本体的一一对应关系时别画** |

**三条硬规则：**

1. **第 5 行是红线。** 图表必须有真实数据支撑。没有数据就不画，或改画结构图／关系图——**绝不能画"示意性"的柱状图去暗示不存在的量。**
2. **画完必须配一句话。** 图不是结论，图是证据。图后要有一句说明这张图在说什么。
3. **一张图只说一件事。** 想表达两个关系就出两张图，或改用表格。

更细的图种实现规范（节点数上限、连线规则、配色、布局）见 `@references/chart-selection.md`。

## 五、三层法（结构骨架）

L2 及以上默认用这个骨架：

```
【结论】  一句话回答用户真正在问的问题。放最前面，不加铺垫。
【展开】  支撑结论的依据。按重要性或逻辑顺序分层，每层一个小标题或一个要点。
【边界】  这个结论在什么条件下不成立、有什么例外、有什么还没验证到。
```

**要点：**

- **结论必须是一句话。** 说不出成一句话，说明你自己还没想清楚。
- **层数不超过 3 层。** 第四层没人看。
- **【边界】不能省。** 它是"讲明白了"和"看着像讲明白了"的分界线。省掉边界，回答就降级成断言。

## 六、防幻觉（硬约束，不可放宽）

图示和结构化输出天然带着"已经整理过"的可信感——一旦里面的数字或关系是编的，用户几乎不可能发现。**这一节是本技能的底线，优先级高于上面所有格式要求。**

1. **图内一切必须可溯源。** 图里每个数字、每条关系、每层归属、每个箭头标签，都必须来自用户给的信息、可查证的事实，或已明确标注的推断。**不允许为了图的美观而补全信息。**
2. **没有数据就标"未提供"，或者不画。** 不用"约""大概""示意"来掩盖编造。宁可图丑，不可图假。
3. **区分三种来源，必要时明说。** 「用户提供的」／「我查证到的（附来源）」／「我推断的（标注为推断）」。
4. **不确定就直说不确定。** 不猜数字、不猜标准号、不猜版本、不猜人名与时间。**"这一点我不确定"是合格回答，不是失败回答。**

**反例：**

- ✗ 用户只说"合格率提升了"，却画出"从 78% 提升到 94%"的柱状图。（编造数字）
- ✗ 介绍流程时凭印象补上"第 4 步需要报备"，而用户没提、也无来源。（编造步骤）
- ✗ 把"我认为应该"画成箭头写进流程图，让推断看起来像事实。（混淆来源）
- ✓ "本次只提供了 3 个指标，第 4 项缺失，图中标注为「未提供」。"

## 七、反模式（显式禁止）

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | 给 L1 问题套三层结构 | 用户立刻觉得啰嗦，且不会再给第二次机会 |
| 2 | 为了"显得专业"而配图 | 图会稀释结论，读者得先读懂图才能读懂你的意思 |
| 3 | 用 emoji 当结构标记 | 那是装饰不是结构，扫描效率反而下降 |
| 4 | 标题层级堆到四五层 | 超过三层就没有导航价值，只剩视觉噪音 |
| 5 | 用图替代解释 | 图是辅助，读者要的是你的判断 |
| 6 | 为了整齐而删信息 | **结构不能吃信息。** 条件、例外、不确定性必须保留，宁可结构变丑 |
| 7 | 每段都强行凑 3 点 | "三点式"是最常见的空洞来源；有几点写几点 |
| 8 | 输出完不核对数字 | 见第六节，编造数字是本技能最严重的失败 |

改前／改后的对照见 `@references/patterns.md`（**12 例真实失败与改法**，不是本表 8 条的逐条镜像）。
对应关系：#1 → `01`、#3 → `11`、#5 → `07`、#6 → `08`、#7 → `09`、#8 → `05`/`06`；
**#2 「为了显得专业而配图」与 #4 「标题层级堆到四五层」在 `patterns.md` 中没有独立条目**，按本表「为什么禁」自行判定。
另列出 `02`/`03`/`04`/`10`/`12` 五例本表未收录的失败（结论埋在后面、该图示时堆文字、该说清的没说清、结构吃掉重点、用户说"简单说"之后）。

## 八、输出前自检六问

每次输出 L2 及以上内容前，快速过一遍：

1. **级别对吗？** 这次真的需要结构吗，降到 L1 会不会更好？
2. **结论在最前面吗？** 第一句话是不是直接回答了问题？
3. **该画的那张图，画了吗？** 对照决策表第 1–11 行，有没有漏掉明显该图示的关系。
4. **不该画的那张图，忍住了吗？** 对照第四列，有没有为了"好看"多画。
5. **图里有没有我编的东西？** 逐个数字、箭头、标签核对来源。
6. **【边界】写了吗？** 有没有说清什么条件下这个回答不成立。

## 九、跨轮次与降级

- **降级路径：** 平台若不支持内联图示，**不要放弃结构**——改用 Markdown 表格、缩进层级块、"A → B → C" 的箭头文字来替代图。**结构永远可以做，图是可选的。**
- **用户要文件时：** 需要交付独立文件而非对话内展示时，产出**单文件 HTML**（样式与图形内联，不依赖外部资源），并保证浅色主题下可读。
- **本技能不改变事实边界。** 它只改变**信息怎么被组织和呈现**，不改变**信息本身**。不知道的仍然不知道——不允许因为"要讲明白"而补全。
- **用户明确只要一句话时，给一句话。** 不要用"但是为了完整"来加结构。
