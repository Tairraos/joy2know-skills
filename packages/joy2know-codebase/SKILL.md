# 晓得 · 代码考古

> 把「一个陌生仓库」变成「架构说明 + 入口链路 + 数据流 + 改造风险清单」。
> 核心纪律：**不读完所有文件**，先靠启发式找出最重要的 20 个，再细读。

## 一、先分清（不做这一步后面全错）

| 概念 | 判定标准 | 处理方式 |
|---|---|---|
| **入口文件** | 程序启动或被框架加载的第一个文件（main / index / app / server / __main__） | 优先级最高，必须首先定位并读 |
| **核心模块** | 被大量其他文件引用、含路由/控制器/模型/服务关键字 | 次优先，构成主流程骨架 |
| **噪音文件** | 锁文件、构建产物、node_modules、dist、vendor | **禁止**纳入阅读，自动跳过 |
| **超大文件** | 体积远超常规（固件 / 数据导出类 JSON 等） | **不跳过**，但**降权**（分数 −8），排在清单末位 |
| **改造风险** | 动它容易出事 vs 动了无碍的区域 | 单独分级输出，见第五节 |

**最容易犯的错：** 试图从头读遍几千个文件。结果上下文被撑爆、重点被淹没，半小时什么也没产出。

## 二、判定与路由

| 情形 | 判定信号 | 走哪条 | 输出形态 |
|---|---|---|---|
| **A. 陌生大仓** | 文件数 > 100 或用户说「刚接手」 | 完整流程：扫描 → 找重点 → 读重点 → 出说明 | 架构说明 + 风险清单 |
| **B. 想看某条链路** | 「登录是怎么走的」「订单流程在哪」 | 只跑入口/关键字定位，专攻一条链路 | 单链路说明 |
| **C. 只问技术栈** | 「这项目用什么写的」 | 只解析依赖清单，不扫描正文 | 技术栈概览 |
| **D. 小改动** | 「帮我改一下这个文件的 bug」 | 降级：直接读该文件，不产出架构文档 | 直接动手 |

**降级判定：** 用户只要一句话概况（「这项目干嘛的」）→ 走 C 的简化版，给一句定位 + 技术栈，不展开九章节。

## 三、工作流

1. **扫描结构。** 跑 `scripts/repo_scan.py <仓库路径> --max-files 20`，得到「最重要的 20 个文件」「依赖清单」「目录职责树」。扫描失败按第六节降级。
2. **读重点文件。** 按清单分数从高到低，只读前 20 个（及其直接依赖），**禁止**读完仓库。
3. **画入口链路。** 从入口文件出发，沿调用/路由/导入关系梳理主流程，画出「谁调谁」的链路。
4. **抽数据模型。** 找出核心模型/表结构/schema 定义，标注关键字段与关联关系。
5. **列外部依赖。** 汇总依赖清单与配置文件里的外部服务（数据库、消息队列、API、密钥）。
6. **标改造风险。** 按第四节规则给每处风险定级（雷区/谨慎/可放心动）。
7. **回报。** 说明结论来源（读的是哪 20 个文件）、哪些靠推断、哪些未确认。

## 四、核心规则

**规则 1：禁止读完整个仓库（红线）**

- 触发条件：面对任何文件数 > 50 的仓库。
- 硬性动作：必须先跑 `repo_scan.py` 拿到打分清单，**只细读清单里的前 N 个文件**（默认 20）。
- 正例：✓ 「我先扫了一遍，最高分是 main.py / users/router.py / db/models.py，先读这三处。」
- 反例：✗ 「我把 3000 个文件都看了一遍……」（上下文必然溢出，且重点丢失）
- 降级路径：脚本不可用 → 用 Glob 找 `main|app|server|index` + 各语言入口，人工取前 20 个。

**规则 2：启发式打分维度必须具体可执行**

- 触发条件：决定「读哪些文件」时。
- 硬性动作：按以下维度和方向打分，**不得**凭感觉挑文件：①入口清单文件名命中 +分；②被引用次数越多 +分（近似统计 import/require/include）；③目录层级越浅 +分；④文件规模适中（200B~60KB）+分，过小或超大降权；⑤路径/文件名含 route/controller/model/service/handler/config 等核心关键字 +分。排除项：锁文件、构建产物、node_modules、dist、vendor、超大固件 JSON。
- 正例：✓ 按脚本输出的「得分 + 命中原因」逐条读。
- 反例：✗ 「我随便挑几个看起来重要的文件看。」
- 降级路径：维度需要裁剪时，至少保留「入口 + 被引用次数」两项，其余可省略但必须说明。

**规则 3：改造风险必须分级，并给判断依据**

- 触发条件：产出任何改造建议前。
- 硬性动作：每处风险归入三级之一，**必须**附判断依据：
  - **雷区**：无测试覆盖、被多处隐式依赖、含全局状态/宏/反射、注释写着「别动」→ 动前必须确认影响面。
  - **谨慎**：有少量引用、逻辑分支多、边界条件不清晰 → 改完要补测试再合并。
  - **可放心动**：纯工具函数、单一调用方、有测试或纯新增 → 直接改。
- 正例：✓ 「utils/date.py（可放心动）：仅被 report 调用，无副作用。」
- 反例：✗ 「这个文件应该能改吧。」（没有依据就是猜测）
- 降级路径：读不到测试信息 → 标「未确认测试覆盖」，按「谨慎」处理而非「可放心动」。

**规则 4：不把推测当事实**

- 触发条件：描述数据流或调用关系时。
- 硬性动作：真正读过文件确认的关系写「已确认」；只按命名/结构推断的标「[推断]」；没读到的写「未读取」。
- 正例：✓ 「支付回调调用 order.finish()（已确认，见 pay/router.py:42）。」
- 反例：✗ 「订单大概会调用库存服务扣减」（没读相关文件就断言）。
- 降级路径：文件过大未读 → 明确说「该文件未读，链路在此中断」。

**规则 5：外部依赖要列全，密钥不回显**

- 触发条件：整理依赖与配置时。
- 硬性动作：从依赖清单 + 配置文件抽取外部服务（DB/队列/API）；遇到密钥/Token **禁止**原样输出，写「<已配置，未回显>」。
- 正例：✓ 「外部依赖：PostgreSQL、Redis、微信支付 API（密钥已配置，未回显）。」
- 反例：✗ 把 `.env` 里的 `SECRET_KEY=xxx` 直接打印出来。
- 降级路径：配置被加密或缺失 → 标「未提供配置，外部依赖待确认」。

## 五、输出格式

**骨架（必须按顺序覆盖）：**

```markdown
# 仓库考古报告：<仓库名>
## 1. 技术栈与依赖概览
  - 语言/框架：<来源：依赖清单>
  - 外部服务：<DB/队列/API>
## 2. 目录职责地图
  - src/  → 业务代码   app/ → 入口与启动
## 3. 核心入口与主流程链路
  - 入口：<文件> → 调用 <文件> → ...（已确认/推断）
## 4. 关键数据模型
  - <模型>：<关键字段与关联>
## 5. 外部依赖清单
  - <服务>：<用途>
## 6. 改造风险清单
  - 🔴 雷区：<文件> — 依据
  - 🟡 谨慎：<文件> — 依据
  - 🟢 可放心动：<文件> — 依据
```

**反模式禁止清单：**

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | 读完整个仓库再开口 | 上下文溢出，重点淹没 |
| 2 | 凭印象挑文件读 | 漏掉真正核心的入口与热点 |
| 3 | 风险不分级、不附依据 | 用户无法判断敢不敢动 |
| 4 | 把推断写成已确认 | 误导改造方向 |
| 5 | 回显密钥/Token | 安全事故 |
| 6 | 只给结论不给读了哪些文件 | 用户无法验证可信度 |

## 六、防幻觉（硬约束，优先级最高）

**本节优先于以上所有格式与流程要求。**

1. **来源三分式。** 每条结论标：用户提供的 / 我读文件确认的（附文件路径:行号）/ 我推断的（标 [推断]）。禁止混为一谈。
2. **没读到的就写「未读取」。** 不因为要凑完整架构图，就为没读到的模块编造调用关系。
3. **不猜版本号与路径。** 依赖版本以 `repo_scan.py` 解析结果为准；配置路径以文件实际存在为准。看不到就写「未提供」。
4. **风险定级必须有据。** 「可放心动」必须有依据，否则一律按「谨慎」输出，禁止为显得利落而低估风险。
5. **不确定就直说。** 「这条链路因为 X 文件过大未读，在此中断」是合格输出。

## 七、按需知识

- 评分维度的细节与排除项清单 → 已在正文第四节规则 2 写死，无需额外参考文件。
- 本技能无附加参考文件，全部规则见正文。

## 八、完成判据

**算做完：** 跑过扫描脚本 + 读了清单前 N 个文件 + 六节骨架齐全 + 风险已分级且每条有依据 + 已标注哪些是推断/未读。

**不自动做：** 不自动改代码、不自动重构、不自动跑测试、不自动提交。改造动作交由用户或其下游流程。

## 九、降级与跨轮次

- **脚本不支持某语言：** 依赖解析覆盖 node/python/go/rust/java/php/ruby；未覆盖语言 → 只给目录树与文件名启发式，依赖项标「未识别，请人工确认」。
- **仓库极大扫不动：** 加 `--no-ref` 跳过引用统计，或减小 `--max-files`；仍不行则只输出目录树。
- **信息不全时的唯一降级路径：** 假设 + 就地标注 + 继续。例如没看到测试文件 → 假设「无测试」并标 [推断]，继续给风险定级，不要连环追问也不要交白卷。
- **跨轮次：** 用户追问「那登录链路具体怎么走」时，默认基于本次已读文件继续，不重新全量扫描。
