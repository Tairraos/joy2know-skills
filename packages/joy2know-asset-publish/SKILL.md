# 发布与驳回

**上传、以及被驳回之后怎么办。**

版本号是被平台占用的资源，**抬错或不抬都是白跑一轮**。本技能把两类驳回的判据做成可执行判据。

---

## 一、上传类型必须与包类型一致

平台**按「类型」挑校验器**：

| 类型 | 校验器找什么 |
|---|---|
| Skill | `<包名>/SKILL.md` |
| Expert | `<包名>/.codebuddy-plugin/plugin.json` |
| Connector | `connector-meta.json` +（`mcp.json` \| `cli.json`） |

专家包的 SKILL.md 内嵌在 `skills/<技能名>/`，**按技能口径查永远查不到根级 SKILL.md**，
于是报「未找到 SKILL.md，请确保该路径文件存在」。

⚠️ **100% 是入口选错，不是包坏了。** 先换上传类型，别改包。

---

## 二、三类驳回（均已实证）

### 第一类：解析失败类

- **`description_en` ≤ 1000 字符**（实测超限即解析失败）。
- **修法**：**别删信息块，并句删冗词**。专家包会**继承内嵌技能的违规** ——
  这类在本地预检里放 `warnings`（未实证不判红，避免「本地红、平台绿」假警报）。
- ⚠️ 中文侧上限未实证 → 预检器只报长度、不判红。

### 第二类：类目被判「深度合成 > AI创作」

⭐ **2026-10-01 闭环并订正结论：改类目就能解决，不必改应用。**

过审路径 = **客服介入 + 按其指定类目重交**。客服原话：
「已查阅相关资产，辛苦只保留【工具 > 办公】类目后重新提交~」→
`musician` **1.6.1 一次过审上架**，而 1.6.1 **与 1.6.0 包内完全相同（只差 `version` 一行）**。

⚠️ 已作废的旧结论：「深度合成类目只对企业开发者开放 → 选不到 → 只能改应用本身」。
驳回原文那句「**至少应包含**『深度合成 > AI创作』」是**审核侧误判**（客服已承认），不是本地选不到。

⚠️ **客服措辞是「只保留」= 只勾这一个**，与驳回原文的「至少应包含」**语义相反**。

**处置顺序**：

1. **先找客服确认**（平台承认属审核问题后会直接给出应选类目）—— 最省事；
2. 拿不到口径时再走**说明层回退四条**（⚠️ 已验证**不充分**：只做回退、类目照旧，仍被同一理由驳回）；
3. 仍被拒**才是**动正文。

**说明层回退四条**（备用，非首选）：
① 说明字段只讲文本产出与写作方法，不把音频/图像/视频说成自己的产物；
② 删掉第三方 AI 服务的档位 / 型号 / 额度 / 商业授权；
③ 触发词由音频成品词回到写作要求词 —— **别砍断原触发路径**；
④ 加显式否定声明，且**声明必须真**：先全包检索 `http / urllib / requests / socket / api_key / fetch(`
并把命中数写进报告。

回退基线取「**最近一个过审版本的说明字段**」，不要凭空重写。

### 第三类：抬版本号的判据 = 「**这个资产有没有被平台审核过**」

> ⚠️ **2026-10-13 订正**：旧判据写的是「有没有走到过『提交成功』」—— **那是错的**。
> 平台的真实口径是（用户给出）：
>
> **「提交后，被审核过的，不论是驳回还是通过，都需要提升版本；
> 自己撤回的，不需要提升版本。」**

| 情形 | 平台占用版本号了吗 | 处置 |
|---|---|---|
| **解析失败**（描述超限 / 入口选错 / 结构不符） | 否 | 修完**同名重传** |
| **提交成功、但在审核前自己撤回**（`withdraw`） | **否** | **不用抬版本**，同版本号可继续用 |
| **被审核过** —— 驳回（`rejected`）/ 通过（`approved` / `published` / `delisted`） | **是** | **必须抬版本号，内嵌它的包一起抬** |

**判断口诀：看它有没有被平台「看过」。**

| 顶层 `status` | 被看过吗 | 要抬版本吗 |
|---|---|---|
| `draft`（从未提交成功，或**自己撤回**后回落） | ❌ 没被看过 | **不用抬** |
| `rejected` / `approved` / `published` / `delisted` | ✅ 被看过 | **要抬** |

两类驳回原文长相不同：带「解析失败」前缀的多为前者，说「所选类目与应用类目不符」的多为后者。

⚠️ 同名重传**已占用过**的版本号，必报：
`解析失败：包内版本号「X」必须大于当前最新版本「X」`。

⭐ **补一条实测（2026-10-13）：删草稿会释放版本号。**
`withdraw → delete` 掉旧 assetId 之后，**可以用原版本号当新包重发**（已实测通过）。
所以遇到「自己撤回的资产、抬版本也不生效（`versionId` 不动）」时，
最干净的处置是 **删掉当新包发**，而不是纠结怎么把版本号抬上去。

⚠️ 另一条实测：**更新版本路径下 `versionId` 可能不变** ——
`submit` 返回 `code:0` 不等于版本生效，**必须回读 `currentVersion.versionId` 是否变化**。

## 三、自检脚本

```bash
# 贴驳回原文或平台状态，拿处置路径
python3 scripts/reject.py --text "所选类目与应用类目不符"
python3 scripts/reject.py --text "解析失败：描述字段超限"

# 反向自检
python3 scripts/reject.py --selftest
```

**退出码**：0 = 可自行处置；1 = 必须抬版本；2 = 用法错。
**判为「必须抬版本」时，脚本会一并列出「谁内嵌了它」的 grep 命令。**

---

## 四、本技能的边界

- **只管上传与驳回**。字段取值 → 「资产字段规范」；检测报告 → 「资产包门禁」；
  平台状态读回 → 「资产状态追踪」；包内内容维护 → 「资产包维护」。
- **「AI 生成服务」措辞要清到整包**（正文 + `references/` 的档位表 / 额度 / 型号门禁同样要清）；
  模型版本用**默认值**不用门禁（任何情形都不问用户版本，用户提了才适配）。
- **内嵌关系与对外说明层分开维护**：`skills[]` / `skills.json` / agent 的 `skills:`
  **保持真实引用**；**技能包被驳回时不要连内嵌关系一起动** —— 驳回是审核结论，内嵌是工程结构。
