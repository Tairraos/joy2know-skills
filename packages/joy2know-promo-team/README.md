# 晓得·项目推广专家团（joy2know-promo-team）

把**一个要推广的东西** —— 一款游戏、一个产品、一项服务、一次活动 —— 变成**一份能直接执行的推广方案**：竞品摸清了、定位定住了、选题打过分了、文案能直接发、排期表在手上、发完的数据有地方记、下一轮改什么有依据。

六位成员各管一棒，主理人「徐策」先体检再分派。

## 核心判断：先体检，不是六棒全上

推广推不动，病因从来不是同一个：可能是人群没找准、可能是卖点讲成了参数、可能是选题与转化脱节、也可能是发了没人记数据。**六棒全开的结果是一份又长又空、谁都不认得的方案。**

所以主理人的第一件事是**体检** —— 从用户给的材料里找证据，判断它到底卡在哪一段，只调对应的人。

```
Phase 0  任务书体检（徐策，引证据作判断）
            ├── 说不清「谁会用、为什么用」 → 司南
            ├── 讲不出「和谁不一样」       → 叶衡
            ├── 定位清楚但不知道发什么     → 霍燃
            ├── 有选题但没有成品           → 言川
            ├── 有成品但不知道先发哪条     → 时叙
            └── 发过了但不知为什么         → 秦度
Phase 1  情报（司南）
Phase 2  定位（叶衡）
Phase 3  选题（霍燃）
Phase 4  内容（言川）
Phase 5  排期（时叙）
Phase 6  复盘（秦度，按需 —— 有数据才做）
Phase 7  汇编为《推广方案》（徐策）
```

## 顺序铁律：情报 → 定位 → 选题 → 文案 → 排期 → 复盘

```
情报（看外面）→ 定位（定我们自己）→ 选题（决定讲什么）→ 文案（决定怎么讲）→ 排期（决定何时讲）→ 复盘（调整下一轮）
```

三条理由：

1. **定位的输入是情报，不是感觉。** 竞品在讲什么、讲到第几遍、受众聚在哪 —— 这些是定位的原料。没做情报的定位是拍脑袋，且没法验证对错。
2. **选题必须挂在定位与卖点上。** 推广的目标是**转化**，不是流量。选题再爆，只要讲的是产品里没人关心的那部分，火完就散。所以选题的输入必须是定好的差异化角度，不能是「最近什么火」。
3. **复盘是唯一能反哺上游的一棒，只能排在最后。** 它吃的是真实发布数据；它给出的结论交回选题策划师，成为下一轮选题的输入 —— 这就是闭环。

允许跳过（用户只要文案时），但主理人必须一句话说清：这份产出是按什么定位写的、缺了哪一步的验证、效果不好时该回头补哪一棒。

## 选题策划师这一棒：12 心法 + 4 基因 + 8 维打分 + 6 形态

这是团队里唯一自带完整量化筛子的一棒，也是与「流量号」的分界线。

- **12 条心法**先筛原料：人群明确、卖点承载、角度不撞车、单点清晰、真实可信、合规安全、不违背定位、平台适配、转化承接、可复用、信源可溯、时效判断。红线命中 1 条淘汰，黄线命中 ≥2 条返工。
- **四大传播基因**：情绪钩子 / 信息差 / 身份标签 / 行动触发 —— 每条选题至少命中 2 条。
- **8 维打分**（每项 1–5，总分 40）：情绪强度、传播动机、角度独家性、人群匹配、时效性、**卖点承载**、形态可行性、**转化承接**。≥35 重点做，30–34 合格，<24 淘汰。
- **六大形态**：短视频 / 图文笔记 / 长文 / 私域话术 / 海报与首屏 / 互动话题。

> 其中「卖点承载」与「转化承接」是推广特有的两维。**一条只有当 ①–⑤ 高分、⑥⑧ 低分的选题，是流量选题，不是推广选题。**

## 内置技能

- **joy2know-clarify（晓得·讲明白）**：结论先行、分层展开、该配图时主动配图
- **joy2know-humanize（晓得·凡人腔调）**：规则表驱动去机器腔调，带脚本自检与改写门禁 —— 文案定稿前的最后一关
- **joy2know-dashboard（晓得·一页看懂）**：表格 → 单文件交互式 HTML 看板 —— 复盘数据直接变成能发给老板的一页

## 适用与不适用

- **适用**：新品/游戏/服务要推但不知从哪下手；内容发了不少但没数据；有数据但不知改什么；要给老板一份能落地的推广方案
- **不适用**：
  - **商业战略咨询** —— 管「怎么推出去」，不管「该不该做、定价多少、要不要转型」
  - **真实投放与账号操作** —— 不代登录账号、不代发内容、不代投广告；产出到「可直接执行」为止
  - **保证数字** —— 不承诺涨粉数、播放量、转化率、ROI
  - **从零做产品定位之前的市场调研**（那是另一个量级的活，本团只做推广所需的情报）

## 目录结构

```
joy2know-promo-team/
├── .codebuddy-plugin/plugin.json   # 配置（expertType: team）
├── settings.json                   # 主理人声明（平台校验器查这个名）
├── setting.json                    # 内容同上，沿用官方模板名，兼容保留

```

> **形态说明**：上面的目录树是**构建后所得包的形态**。仓库里的**源包**只有
> `.codebuddy-plugin/plugin.json`、`agents/`、`skills.json`、`settings.json`、`setting.json` 与 `README.md` ——
> `avatars/` 由构建从仓库根 `avatars/joy2know-promo-team/`（团队图标）+ `avatars/<成员名>.png`（成员图标）注入；

> （本包内不存副本，避免同一技能两份、改一处漏一处）。
