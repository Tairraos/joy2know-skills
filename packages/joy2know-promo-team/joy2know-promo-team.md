**本节踩坑记录（与包本身无关，与检测方法有关）**：第一轮反向验证时，**7 组样本全部「无输出」**，且基线副本也报三条红灯。
逐项排查后确认是**样本环境构造问题**，与包无关，两条根因：

1. **副本目录名必须保持包名。** selfcheck 按**目录名**校 `plugin.name`，把副本放在 `/tmp/.../s0-baseline/` 会连带报
   `plugin.name 'joy2know-promo-team' 与目录名 's0-baseline' 不一致` 与 `plugin 字段与 name 不一致` 两条**假红灯**。
   改为 `<样本名>/joy2know-promo-team/` 的双层结构后消失。
2. **头像真源的回退路径是「父目录的父目录」。** `selfcheck.py` 取 `dirname(base)/avatars/<包名>.png`
   —— 软链放在样本目录里无效，必须放在**样本目录的上一级**。放对后基线恢复全绿。

**另一条方法教训**：`grep -E "^\[XX\]"` 匹配不到，因为 selfcheck 的输出行有**两个前导空格**。
判据若写成行首锚定，会在「没抓到任何东西」时**静默输出空结果**——看起来像「全部通过」，性质等同于「一项没查却报绿」。

**一句话回答：本包的核心结构如果坏掉，是哪一步会亮红灯？**
→ 平台解析层（配置字段 / 成员对应 / settings 双文件 / 主理人前缀与路径 / 描述字数 / 头像路径）坏了 → `selfcheck.py` 亮红灯，
已用 7 组错样本反向验证，且每组只亮对应红灯。
→ 交付形态层（zip 第一层、内嵌副本漂移、头像注入）坏了 → 解压后的交付形态自检亮红灯（39 项），本轮已实测。
→ **有一类不会亮红灯**：6 个成员 agent 的**提示词内容质量**（路由是否完备、边界是否可执行、方法论是否正确）——
  任何自动校验都读不出这个，只能靠人工审阅 + 真实跑一次团队。这是本包最大的未覆盖面（见第六节 1）。
