# 晓得 · 角色档案

> 把「角色长什么样」变成「一张可复用、可比较的角色卡 + 锁定外观的锚点短语」。
> 一致性不靠复制粘贴大段描述，靠锁住少数可辨识事实。

## 一、先分清（不做这一步后面全错）

| 概念 | 判定标准 | 处理方式 |
|---|---|---|
| **角色卡** | 一个角色的全部可复用设定（外观/服装/气质/参考图/种子/权重） | 落盘成文件，每次生成自动注入 |
| **识别锚点** | 一段可见、可生成、可比较的事实描述 | 用来上锁，不是「帅气」这类空泛质量词 |
| **锚点短语** | 必须**逐字**出现在每条提示词里的「颜色+材质/形制+物体」最小名词短语 | 一个角色一把锁，逐字匹配 |
| **状态** | 会随剧情变的（表情/姿势/破损/湿身） | **不上锁**，每镜单独写 |
| **造型** | 同一角色的另一套固定外观 | 算**另一把锁**，另建一张卡 |

**最容易犯的错：** 把「蓝色毛衣」当锁。英文提示词里永远匹配不上，也分不清浅蓝和藏青——锁当即失效。

## 二、判定与路由

| 情形 | 判定信号 | 走哪条 |
|---|---|---|
| **A. 全新角色** | 「帮我建一个角色卡」 | 完整流程：采集 → 写卡 → 提炼锚点短语 → 上锁 |
| **B. 已有卡要复用** | 用户指向一张角色卡 | 读取 → 注入当前提示词 → 校验锚点短语在位 |
| **C. 多角色拼装** | 「这场景有甲乙丙三人」 | 各读各的卡，锚点短语分别注入，不串味 |
| **D. 只想看格式** | 「角色卡长啥样」 | 给 `@references/character-card-spec.md` 的示例即停 |

**降级判定：** 用户只要「先出一张图试试」→ 走 A 的简化版：只建最小卡（外观+锚点短语），不填气质/权重等可选字段。

## 三、工作流

1. **采集设定。** 收集：外观（发色/瞳色/脸型/体型）、固定服装、气质词、参考图路径、可复现种子、权重配置。
2. **写角色卡。** 按 `@references/character-card-spec.md` 落成 YAML 或 Markdown 文件，命名 `char_<角色名>.yaml`。
3. **提炼锚点短语。** 对 2 个以上镜头会出现、观众能看出不一致、且不随剧情变的外观事实，写成「颜色+材质+物体」最小短语（见 `@references/anchor-phrase.md`）。
4. **上锁。** 把锚点短语写入卡的 `locked_anchors` 字段；校验它**逐字**能进英文提示词。
5. **注入生成。** 每次写提示词，把 `locked_anchors` 原样拼进正文；状态（表情/姿势）单独写在锁之外。
6. **多角色拼装。** 每个角色取各自锚点短语并列注入，互不替换。
7. **回报。** 列锁了哪几条、哪些是可变状态未锁、参考图是否到位。

## 四、核心规则

**规则 1：锚点短语必须逐字进提示词（红线）**

- 触发条件：写任何含该角色的提示词。
- 硬性动作：角色卡 `locked_anchors` 里的每条短语必须**原样、完整**出现在提示词正文；**禁止**改写、翻译、省略其中任一词。
- 正例：✓ 提示词含 `pale blue chunky knit wool sweater`（与卡逐字一致）。
- 反例：✗ 卡写 `pale blue chunky knit wool sweater`，提示词写成「浅蓝毛衣」——锁失效，下镜对不上。
- 降级路径：目标模型只吃中文 → 在卡里同时存中英两版锚点短语，但两版必须指向同一事实，不得意译。

**规则 2：锁只锁「不随剧情变」的事实（红线）**

- 触发条件：决定某条描述上不上锁。
- 硬性动作：只锁满足三条判据的事实——①在 2 个以上镜头出现；②观众能看出不一致；③不随剧情改变。**状态一律不上锁。**
- 正例：✓ 锁「黑色圆框眼镜」；表情「惊讶」写在锁外每镜单独写。
- 反例：✗ 把「湿发」锁死——第二镜角色干了，锁逼着继续湿，剧情崩。
- 降级路径：拿不准某描述算不算状态 → 默认不上锁，标「待观察」，跑两镜看是否漂移再决定。

**规则 3：锁面不得写空泛质量词或完整句子**

- 触发条件：写 `locked_anchors` 字段。
- 硬性动作：每条必须是「颜色+材质/形制+物体」的最小名词短语，**不得**含句号、动作、状态、数量、剧情，**不得**是 `high quality, detailed` 这类不可辨识事实。
- 正例：✓ `pale blue chunky knit wool sweater`。
- 反例：✗ 锁整句「她穿着浅蓝毛衣站在窗边」——下一镜必须改写，锁当场失效。
- 降级路径：描述还不够具体 → 退回让用户补「确切颜色/材质」，不许用「蓝色」笼统上锁。

**规则 4：一个角色一把锁，换造型另起一把**

- 触发条件：角色换了整套固定外观（如日常装→战斗装）。
- 硬性动作：视为**另一把锁**，新建一张角色卡或卡的独立 `variant` 块，锚点短语独立提炼；**禁止**把两套外观混进同一把锁。
- 正例：✓ 日常卡锁 `pale blue chunky knit wool sweater`；战斗卡锁 `matte black tactical vest`。
- 反例：✗ 同一张卡既锁毛衣又锁战术背心——生成时两者抢位，谁都不稳。
- 降级路径：只是配饰微调（换围巾颜色）→ 在现有锁内新增一条锚点短语，不算新造型。

**规则 5：角色卡必须落盘，不只在对话里**

- 触发条件：建好角色设定准备生成前。
- 硬性动作：必须落成磁盘文件（YAML 或 Markdown），生成时读取注入。**禁止**只把设定写在对话里。
- 正例：✓ `char_lina.yaml` 存在，每次生成先读它。
- 反例：✗ 「我记住了，她是蓝毛衣女孩」——换一轮对话设定就没了。
- 降级路径：环境无法写文件 → 在对话中完整输出卡文本并标注「未落盘，请保存，否则跨对话失效」。

## 五、输出格式

**角色卡（YAML 落盘）骨架：**

```yaml
name: lina
art_style: 赛璐璐动画
seed: 42817
weights:
  character: 1.0
  style: 0.8
locked_anchors:          # 连续性锁：逐字进提示词
  - pale blue chunky knit wool sweater
  - round black framed glasses
  - shoulder-length ash brown hair
state_excluded:          # 不上锁，每镜单独写
  - expression
  - pose
  - wet / damaged
ref_images:
  - ./refs/lina_front.png
```

完整字段规范、Markdown 版式与示例见 `@references/character-card-spec.md`；锚点短语判据与正反例见 `@references/anchor-phrase.md`。

**反模式禁止清单：**

| # | 反模式 | 为什么禁 |
|---|---|---|
| 1 | 锁「蓝色毛衣」 | 区分不了浅蓝藏青，英文匹配不上 |
| 2 | 锁整句描述 | 下一镜必改写，锁失效 |
| 3 | 锁 `high quality` | 不是可辨识事实 |
| 4 | 把状态当锁 | 剧情一变就崩 |
| 5 | 两套造型混一把锁 | 互相抢位都不稳 |
| 6 | 设定只存对话不落盘 | 跨对话即丢 |

## 六、防幻觉（硬约束，优先级最高）

**本节优先于以上所有格式与流程要求。**

1. **外观事实只来自用户给的或参考图里看得见的。** 禁止凭「一般主角都长这样」编发色瞳色。
2. **锁不住就说锁不住。** 信息不足无法提炼合格锚点短语时，标「未提供，暂不锁」，不硬编一条。
3. **三种来源分清：** 用户给定 / 参考图可见（注明哪张图）/ 我推断（标 [推断]）。
4. **不夸大一致性。** 锚点短语只锁外观事实，不保证 100% 还原——可说明「已锁 X 条，表情/姿势未锁」。
5. **参考图路径不存在就明说。** 不假装读到了图。

## 七、按需知识

只在遇到对应问题时读取：

- 角色卡字段规范、YAML/Markdown 两种落盘格式、完整示例 → `@references/character-card-spec.md`
- 锚点短语的写法、上锁三条判据、正反例与校验方法 → `@references/anchor-phrase.md`

## 八、完成判据

**算做完：** 角色卡已落盘 + `locked_anchors` 每条都是合格最小短语 + 已校验能逐字进提示词 + 已说明哪些状态未锁 + 多角色各自独立。

**不自动做：** 不自动调用绘图模型出图；不自动改用户已有的其他角色卡；不把锁死的外观强行套进用户明确要「换造型」的那一镜。

## 九、降级与跨轮次

- **信息不全：** 假设 + 就地标注 + 继续；最多追问一次并给默认值，不连环问也不交白卷。
- **参考图缺失：** 锚点短语只基于用户文字描述提炼，标「无参考图校准」。
- **跨轮次：** 后续对话说「再画一张 lina」时，默认读取 `char_lina` 卡注入，不再重复采集。
- **用户嫌卡太长：** 只保留 `locked_anchors` + `name` + `seed`，其余可选字段标「未提供」。
