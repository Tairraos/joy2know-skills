## 四、门 3 · 合理性结论

- **规则是否自洽**：⚠️ **发现一处**：规则 4「产出任何正则表达式时**必须**逐字符/逐段解释」是**硬性动作且没有优先级声明**，
  而 §二 降级判定允许「用户只要极短答案 → 省去拆解与路由」、§九 也写「用户只要最短答案：可省拆解与路由」。
  规则 1 专门写了「本条优先于第五节的格式要求」来化解同类冲突，**规则 4 缺这句**，使用者无从裁定。
  除此以外 6 条规则互不打架；规则 2（定级）与规则 3（前置动作）是递进关系而非并列冲突。
- **推断是否标注为推断**：✅ §六.1/2/3 要求不确定标 `[假设]`、三种来源分清、缺失标「未提供」不掩盖。
- **错误提示是否可指导下一步**：不适用（无脚本）。可类比的是模式库 §五 给了**二次确认话术模板**
  （「这条会删除 [对象]，不可逆。请先确认 [范围]，或我先给你 SELECT/备份版？」）—— 是「发生了什么 + 你可以怎么做」。
- **边界是否优雅**：✅ §二 降级（极短答案）、§九 四条（无样例 / 环境不明 / 跨轮次 / 最短答案）、
  规则 2/3/5 各自带降级路径（拿不准往高标、坚持执行要逐字确认、环境不明给假设并标差异）。
- **零依赖是否守住**：✅ 结构性成立（无 `scripts/`、无 import、无网络调用）。
- **值来源是否可追溯**：✅ §六.3 要求缺失标「未提供」、§六.2 三种来源分清；
  模式库条目都带「关键点」列解释风险来源，可追溯到具体机制而不是笼统感受。
- **规则 2 的等级判定是否稳定可复现**：⚠️ 部分 —— 四级定义里「谨慎 = 影响可控但有副作用」中「影响可控」
  没有可操作判据，这正是缺陷 1 的成因（递归改根目录被当成「可控」）。见第六节。

**已知缺陷**（**消解情况见本节末「修复记录」**）：

- **【已修 2026-09-23】** **缺陷 1（中）· 递归作用于根目录的写法被标成「谨慎」，与本文件对「谨慎」的定义冲突。**
  `danger-patterns.md` §二 与 §六 把 `chmod -R 777 /` 与 `chown -R user /` 标为**谨慎**，
  而 §一 对谨慎的定义是「**影响可控**但有副作用」，并在同页写明原则「拿不准就往高一级标」。
  递归变更根目录的权限/属主既不可逆也谈不上影响可控 —— 这正是本技能存在的意义（防止用户误伤系统）。
  **倾向性判断**：这两条应至少为「危险」，酌情「极高危」。若作者本意是「按命令族定级（chmod 本身即谨慎）、
  风险靠『安全替代』列化解」，那么表头「危险写法」与「等级」两列的口径就需要写清楚，否则读者按字面取值。

  —— 口径不统一。建议明确「覆盖类操作」的统一档位（截断清空 vs 可交互确认覆盖是否分档）。

**【已修 2026-09-23 · 版本 1.1.0 → 1.2.0】修法**（本包为纯文档技能，无脚本）：

**定级口径统一（缺陷 1 + 2 同一根因：定义不足以判定这两类），取「向更高危一侧」的方向：**

1. **修订 §一 的四级定义**，并把两条易错分界线写成明文：
   - **极高危** 增加「**或使系统（或服务）不可逆失效**」，判定信号补 `chmod`/`chown` 递归作用于根目录、`dd if= of=/dev/*`、`find -delete`、`git clean -fd`。
   - **危险** 增加「**或覆盖已存在文件致其原内容不可逆丢失**」，判定信号补 `:> f`·`> f`（截断）、`cp a b`（b 已存在）、`mysqldump > 已有备份`。
   - **谨慎** 明确写「**不含「覆盖已有内容」**」，把原「单文件写入」改成「**写入不存在的文件（新建）或追加**」，`chmod` 限定为「**非递归、目标明确的**」。
   - **新增两条分界线**：① 是否覆盖已有内容 → 危险；② 是否递归作用于根/系统级路径 → 极高危。
     并写明「**命令族本身不决定等级，作用范围才决定等级**」—— 原实现按命令族直觉给 `chmod` 定谨慎，于是 `chmod -R 777 /` 被漏成谨慎。

2. **逐条改等级**（只升不降，符合「拿不准往高标」原则）：

| 条目 | 原等级 | 新等级 | 依据 |
|---|---|---|---|
| `chmod -R 777 /` | 谨慎 | **极高危** | 递归改系统级权限，SSH/服务可能直接失效，恢复需重装（判据②） |
| `chown -R user /` | 谨慎 | **极高危** | 同上 |
| `cp a b`（b 已存在） | 谨慎 | **危险** | 覆盖已存在文件致原内容不可逆丢失（判据①） |
| `mysqldump ... > out.sql`（out 已存在） | 谨慎 | **危险** | 同上；且旧备份往往在需要它时才发现没了 |
| `:> file` / `> file` | 危险 | 危险（不变） | 判据①，新定义下**有据可依**（原先无判据支撑） |

3. **同步 `SKILL.md` 规则 2**（跨文件冲突）：原写「`chmod`」= 谨慎，与模式库改后的极高危冲突；
   现改为「**非递归、目标明确的** `chmod`·`chown`」= 谨慎，极高危档明列「**`chmod`·`chown` 递归作用于根目录**」，
   并加一句「判据只看两条……命令族本身不决定等级」。
